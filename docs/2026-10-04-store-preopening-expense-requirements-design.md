# 门店筹建费用需求分析与设计

- 日期：2026-10-04
- 状态：需求与设计评审稿，尚未开发
- 来源：筹建费用思维导图、需求讨论及审批模板标记与独立分类补充要求
- 目的：独立核算门店筹备阶段的费用，复用银行流水和钉钉审批数据，避免与日常经营费用混算。

## 1. 已明确的需求

1. 门店筹备阶段的支出形成一张独立的筹建费用报表；一个门店只有一张，不按月份、账期拆分。
2. 银行流水与日常业务共用；筹建对账确认后，对应流水显示已匹配。
3. 新增筹建审批单对账，核对银行支出和审批单，只选择筹建费用分类，不选择入账月份。
4. 筹建费用分类独立维护，支持一级、二级分类，不与现有 `/categories` 日常费用分类共用。
5. 筹建报表由确认的筹建对账记录生成，展示累计支出、各分类总金额与占比、支出明细。
6. 所有记录归属具体门店；对账结束后可以封账，封账后不能继续筹建对账或修改统计数据。
7. 一张审批单不能同时被日常和筹建两个对账模块使用。
8. `/dingtalk` 的审批模板列表新增「是否是筹建费用」列；标记为筹建费用的模板，其下审批单进入筹建费用流程。

筹建报表金额已确认按审批单费用原额统计、审批单去重，不按银行流水匹配金额分摊。后续章节中的入口、历史数据迁移和解封规则属于建议设计，需本次 review 确认。

## 2. 模块边界

| 项目 | 日常经营费用 | 筹建费用 |
| --- | --- | --- |
| 审批来源 | 非筹建模板的审批单 | 筹建模板的审批单 |
| 银行流水 | 共用现有流水 | 共用现有流水 |
| 分类 | 现有日常费用分类 | 独立筹建分类 |
| 时间归属 | 入账月份、账期 | 门店唯一筹建报表，无账期 |
| 支出统计 | 日常总览、财务报表 | 筹建报表 |
| 毛利、净利润 | 按日常报表口径计算 | 不进入日常毛利、净利润和分红利润 |
| 银行余额 | 按现有真实收付款规则计算 | 仍参与真实银行余额计算 |
| 封账 | 月度账套封账 | 独立筹建报表封账 |

筹建模板标记只决定业务归属，不代表已匹配，也不直接产生筹建报表支出。只有确认对账记录才计入筹建支出。

## 3. 审批模板标记与同步

### 3.1 页面交互

在 `/dingtalk` 审批模板列表增加「是否是筹建费用」列，使用「是／否」开关，默认否。权限沿用管理员模板维护权限。

- 保存时显示 loading，失败显示明确错误，成功后再更新开关状态。
- 切换前提示：该模板下审批单将归属筹建／日常费用流程。
- 模板启用与筹建标记互相独立；筹建标记不绕过同步启用条件。
- 模板同步名称、结构、字段映射时，保留管理员设置的筹建标记，不能被钉钉同步覆盖。
- 在审批列表与详情显示「筹建费用」标签，方便识别归属。

### 3.2 归属规则

建议在审批实例和费用明细上保存业务归属 `operating / preopening`，不能仅在显示时临时读取模板开关，否则修改模板可能导致历史支出消失或换表。

- 新同步审批单继承模板业务归属；重复同步不重置已有确认归属。
- 日常对账候选排除筹建审批单；筹建候选只显示筹建审批单。
- 两类候选均排除撤销、拒绝及其他现有不可对账审批状态。
- 模板停用后保留已同步记录和既有统计，不删除历史数据。
- 分类字段使用所属业务的分类空间，不能把同名日常分类直接套用为筹建分类。

### 3.3 已有模板修改标记（建议）

用户要求模板下审批单进入对应流程，首次启用筹建标记时应处理已经同步的历史单据，不能只作用于以后新增单据。

建议切换前检查该模板全部已有实例：

1. 全部未匹配、未封账：事务内调整模板及实例、明细归属；旧业务的分类清空，等待重新选择目标业务分类。
2. 存在有效匹配或受封账保护的记录：阻止直接切换，提示受影响记录数量；必须先按原流程撤销匹配并处理封账限制。
3. 不自动搬迁已确认支出，不静默改变已发布报表；若确实需要迁移，另行评审一次性迁移方案。

切换检查与确认对账使用相同的归属锁定规则，避免检查结束后有其他操作插入匹配记录。

## 4. 独立筹建费用分类

建议新增 `/preopening-categories` 页面，在后台设置中提供「筹建费用分类」入口，与 `/categories` 明确区分。

- 一级、二级树形维护，支持新增、编辑、停用和删除未引用分类。
- 对账必须选择二级分类；仅一级分类不能确认。
- 名称去除首尾空白，筹建分类范围内不允许重名，沿用现有分类名称唯一规则；与日常分类重名不冲突。
- 停用分类排到列表末尾，不再用于新匹配，历史报表仍可显示。
- 已引用分类禁止物理删除；可停用。
- 已引用二级分类不允许直接更换父分类，避免历史分类汇总改变。
- 保存匹配时记录分类 ID 与名称快照，历史明细显示当时的分类名称。
- 筹建分类不继承「门店预充值」「备用金/借款」等日常分类特殊排除规则；本期筹建模块不预设特殊分类。

建议分类由公司统一维护、各门店共用，第一期不额外增加每店一套分类的复杂度。

## 5. 筹建审批单对账

### 5.1 入口与布局（建议）

门店工作台新增「筹建费用」入口，路由 `/store-ledgers/[storeId]/preopening`，包含「筹建报表」「筹建审批单对账」两个 Tab。

- 复用门店切换；当前门店来自路由，不再增加重复的门店选择。
- 不显示账期选择，不受其他页面遗留的 `period` 参数限制。
- 对账列表可按发生日期范围、金额、对方户名、审批编号、匹配状态筛选；日期只筛选记录，不构成账期。
- 页面显示筹建状态；封账后保留查看、搜索、明细预览，隐藏或禁用修改入口。

### 5.2 匹配交互

复用现有审批单匹配弹窗的金额、日期、费用明细和凭证预览布局，移除入账月份字段；分类控件改为独立筹建分类。

- 左侧银行支出，右侧筹建审批单；审批单按整单候选展示，明细逐行设置分类，支持批量设置。
- 推荐匹配复用金额及日期接近程度规则，不新增另一套评分。
- 无明细表格的审批单按整单生成一条费用明细，仍支持分类和凭证。
- 图片显示缩略图，点击放大并切换图片；普通文件显示文件名及打开入口。
- 钉钉附件使用现有外部链接／access-url，本地上传附件使用本地下载，不要求重新同步或重新上传。
- 保存、撤销、详情请求显示 loading，并展示后端业务错误。

### 5.3 强制校验

后端必须校验，前端过滤不能代替：

- 审批单与流水属于当前门店；审批单归属筹建业务。
- 筹建报表未封账，源审批状态允许匹配。
- 所有需要入账的费用明细已选择有效、启用的筹建二级分类。
- 审批单没有被另一业务占用；即使明细不同，也按整张审批单互斥。
- 流水没有被日常费用、收入或其他业务占用；第一期不支持一笔流水跨两类费用拆分。
- 共享流水的特殊属性沿用现有规则，不自动把「股东分红／注资」等改为可匹配筹建费用；筹建专用报销需使用允许匹配的普通支出流水。
- 匹配金额为正且不超过流水及审批单剩余可匹配金额；重复点击、并发请求不能重复占用或入账。
- 「手工标记已匹配」仅为状态标记，不生成筹建费用，不得当作实际对账记录统计。

### 5.4 金额口径（已确认）

用户确认：审批单多少就是多少。匹配决定审批单是否进入筹建报表，匹配金额不作为筹建费用统计金额。

- 累计筹建支出 = 有效筹建对账中已匹配审批单的费用金额之和，按审批实例 ID 去重，每张审批单只计入一次。
- 分类金额 = 这些审批单中对应分类的费用明细原额之和，按费用明细 ID 去重。
- 不按本次付款金额、明细剩余额比例进行分摊，不提供分摊金额调整表单。
- 一张审批单关联多笔流水，不重复计入审批单总额和费用明细金额。
- 有费用明细表格时，按各费用明细原额计入所选二级分类；没有费用明细时，按审批单总额作为一条费用记录。
- 审批总额与有效费用明细合计不一致时，提示核查，不能通过分摊或重复统计掩盖差异；具体异常需沿用审批解析与核查流程。
- 撤销其中一笔匹配但仍存在其他有效筹建匹配时，审批单仍计入一次；最后一笔有效匹配被撤销后，该审批单及明细退出统计。
- 银行流水匹配金额仍用于对账和占用额度校验，银行余额仍按实际流水计算，两者不改变审批费用原额。

示例：审批单 10,000 元，装修明细 6,000 元、设备明细 4,000 元。确认一笔 5,000 元流水与该审批单匹配后，筹建报表计入审批费用 10,000 元，其中装修 6,000 元、设备 4,000 元；后续再匹配另一笔流水，总支出仍为 10,000 元。银行余额按各笔实际收付款计算。

## 6. 筹建报表与封账

### 6.1 报表展示

采用简洁报表布局，不增加没有业务意义的统计卡片：

1. 顶部：门店名称、「筹建费用报表」、进行中／已封账状态、封账时间。
2. 主指标：累计筹建支出。
3. 分类统计：一级展开二级，金额、占总筹建支出的比例；可使用横向条形图辅助比较。
4. 支出明细：流水发生日期、审批申请日期、费用内容、一级分类、二级分类、审批费用金额、审批编号、对方户名、备注、凭证。
5. 点击分类查看对应支出明细，支持返回；图片交互与对账明细一致。

分类统计、累计指标与明细合计必须一致；无支出时比例显示「/」，不得出现除零异常。报表不提供按月份切换，不把日常经营收入、手续费、快驴采购或主要支出凭证自动加入筹建统计。

HTML/PDF 导出可复用现有报表能力，但原始筹建需求未明确要求导出，建议作为后续范围，不默认加入第一期。

### 6.2 封账规则

- 每个门店只保存一个筹建报表状态，不允许通过新增月份绕过封账。
- 管理员封账前二次确认，显示累计金额和已匹配记录数量；保存封账人、时间及留痕。
- 封账后禁止新增、编辑、撤销筹建匹配，禁止修改影响历史统计的分类归属和模板业务归属。
- 关联流水不得删除或修改金额、方向、日期、门店、付款情况及流水属性等影响关联和余额的字段；是否允许仅改备注可单独约定。
- 日常月度封账与筹建封账相互独立；共享流水编辑仍须满足其已有保护规则，不因筹建无账期而绕过。
- 钉钉同步可继续保存来源更新，但不能覆盖封账后已确认的归属、金额和分类；来源变化应记录冲突，供查看。

原图强调封账后不再产生筹建费用。建议第一期不提供解封；如需纠错，另行确认管理员解封权限、原因必填及审计要求，不默认实现。

## 7. 数据与接口设计建议

现有系统已有 `approval_templates`、审批实例、费用明细及 `expense_bank_matches`，建议复用，不再建一套审批和流水同步。

| 对象 | 建议变更 | 用途 |
| --- | --- | --- |
| 审批模板 | `is_preopening_expense`，默认 false | 模板业务路由配置，同步保留 |
| 审批实例／费用明细 | `expense_scope`，默认 operating | 保存明确业务归属，支持筛选与互斥 |
| 门店筹建状态 | 门店唯一约束，status、closed_at、closed_by | 无账期的筹建报表与封账 |
| 筹建分类 | 独立表，parent_id、name、enabled、sort_order | 独立分类空间 |
| 匹配记录 | 业务范围与审批单／费用明细关联 | 共用匹配状态，筹建 accounting_period 为空；匹配金额仅用于对账 |
| 筹建费用分类归属 | expense_item_id、category_id、名称快照 | 按费用明细原额分类统计，不新增分摊金额表 |
| 审计日志 | 模板切换、分类维护、确认／撤销、封账 | 可追溯 |

建议保留日常匹配 `accounting_period` 必填校验，筹建为空，不把字段整体放宽。

接口职责建议：

- 模板更新：标记切换预检查和原子保存。
- 筹建分类：独立 CRUD／停用接口。
- 筹建对账：候选、明细、确认、撤销；确认与互斥采用数据库事务及必要行锁。
- 筹建报表：按门店汇总、分类明细；无账期参数。
- 筹建封账：原子检查并锁定门店筹建状态。

所有日常统计查询均需排除筹建范围，覆盖门店总览、财务报表及导出、分析接口、分红净利润来源。不能仅在页面层隐藏筹建记录。

## 8. 历史数据与兼容

1. 新字段默认日常业务，保证现有系统统计不因升级自动改变。
2. 管理员明确标记筹建模板后，按第 3.3 节处理已有审批。
3. 不自动复制日常分类；筹建分类由管理员维护。
4. 不自动创建筹建匹配，不自动迁移现有财务金额。
5. 已同步附件继续引用原审批／费用明细附件，不复制文件，不以分类名称作为附件关联依据。
6. 升级前后校验未变更业务归属门店的日常报表金额一致，银行实时余额一致。

## 9. 开发阶段与验收

文档 review 后再开始开发，当前未承诺具体工期。

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 1 | 归属字段、筹建状态、独立分类、模板标记 | 历史默认不变，模板切换和同步保留配置正确 |
| 2 | 筹建候选、匹配、撤销、互斥及审批去重 | 无账期匹配成功，跨模块重复占用被拒绝 |
| 3 | 门店页面、分类统计、明细凭证与封账 | 指标／分类／明细一致，封账保护完整 |
| 4 | 回归测试、本地验收，再部署 | 日常报表与银行余额不回归，线上服务正常 |

重点验收场景：

- 标记筹建模板后，已有未匹配审批和新同步审批均进入筹建候选，日常候选不再出现。
- 已匹配模板切换归属被拦截并显示原因；并发切换与对账不能绕过检查。
- 筹建分类新增、重名、停用、被引用删除及一级分类匹配均有明确反馈。
- 只选择一级分类无法保存；二级分类可以确认；无费用表格审批也可正常对账。
- 同一审批单不同明细不能跨模块匹配；同一流水不能重复占用。
- 部分付款匹配后按审批单费用原额统计；多笔付款关联同一审批单时只计入一次，分类按费用明细原额统计。
- 撤销其中一笔匹配但仍有有效匹配时不减支出；撤销最后一笔有效匹配后移除该审批费用。
- 钉钉图片占位附件可以直接缩略图预览，无需先下载到本地；PDF／其他附件可打开。
- 筹建支出不进入日常净利润，但实际收付款仍正确影响银行余额。
- 封账后新增、编辑、撤销、关联流水编辑及模板切换均受到后端保护；查看正常。
- 日常模块及导出金额保持原有口径。

## 10. 本次 review 重点

以下事项尚属建议，需要评审确认：

1. 有已匹配记录的模板不允许直接修改筹建标记，需先撤销原匹配，是否接受？
2. 筹建分类公司统一维护、各门店共用，是否合适？
3. 门店下「筹建费用」入口和报表／对账两个 Tab 是否合适？是否还需要全局入口？
4. 第一期封账后不支持解封；报表导出暂不纳入，是否符合范围？

模板业务标记、独立分类与按审批费用原额去重统计已经作为明确需求写入；以上 review 项不是已开发行为。
