# 蘑说财务管理系统交互与页面汇总

生成时间：2026-08-28

来源系统：`/Users/ompeak/Documents/蘑说财务管理系统`

> 说明：本文档整理的是现有 Python + CustomTkinter 单机版系统的页面与交互，用作 `fin-hub` 新项目开发参考。现有系统不等同于新版 PRD，尤其缺少“支出明细行级对账”“供应商”“操作日志”“严格封账写入拦截”等新版能力。

## 1. 全局框架

现有系统采用左侧固定导航 + 右侧页面内容区。

- 默认首页：`/dashboard`
- 窗口尺寸：`1280x800`，最小 `1080x700`
- 页面基类：`app/ui/pages/base_page.py`
- 路由注册：`app/ui/pages/__init__.py`
- 主窗口与侧边栏：`app/app.py`
- 全局事件：`EventBroker`
- 全局轻提示：`ToastManager`

侧边栏分组：

| 分组 | 菜单 | 路由 |
|---|---|---|
| 首页 | 首页仪表盘 | `/dashboard` |
| 总管理 | 门店管理 | `/stores` |
| 总管理 | 支出科目 | `/categories` |
| 总管理 | 钉钉同步设置 | `/dingtalk` |
| 门店账套 | 门店账套列表 | `/workspace` |
| 门店账套 | 营业收入 | `/workspace/{store_id}/revenue` |
| 门店账套 | 审批单管理 | `/workspace/{store_id}/reimburse` |
| 门店账套 | 银行流水 | `/workspace/{store_id}/bank` |
| 门店账套 | 对账工作台 | `/workspace/{store_id}/reconcile` |
| 报表 | 财务报表 | `/report` |
| 系统 | 系统设置 | `/settings` |

账套内页面依赖 `store_id` 上下文。若未先选择门店，会显示“请先在门店账套列表中选择一个门店账套”的配置横幅。

## 3. 主要页面交互

### 3.1 首页仪表盘

页面：`app/ui/pages/dashboard.py`

交互：

- 展示全公司概览指标。
- 展示快捷入口卡片。
- 点击快捷入口调用 `navigate(route)` 跳转。

可参考点：

- 首页适合作为“待处理事项聚合页”。
- 新版 Web 可强化为：待匹配流水、未分类明细行、未设归属账期、同步失败、未封账账套。

### 3.2 门店管理

页面：`app/ui/pages/stores.py`

主要区域：

- 搜索框：搜索门店名称/联系人。
- 启用/全部分段筛选。
- 门店表格。
- 选中行后的操作条。

交互：

- `+ 新建门店`：打开 `StoreFormModal`。
- 双击表格行：编辑门店。
- `编辑`：打开编辑弹窗。
- `停用`：打开二次确认弹窗；停用后历史数据保留。
- 停用门店在“全部”筛选中可见，可重新启用。
- 无数据时显示空态；搜索无结果时显示搜索空态并支持清除搜索。

弹窗字段：

- 门店名称
- 钉钉部门 ID
- 联系人
- 电话
- 地址
- 备注

### 3.3 支出科目管理

页面：`app/ui/pages/categories.py`

主要区域：

- 左侧两级科目树。
- 右侧科目详情表单。

交互：

- `+ 新增大类`：打开新增大类弹窗。
- 选择左侧科目：右侧加载详情。
- 双击科目：打开编辑科目弹窗。
- 选中大类后，`+ 新增小类` 可用。
- 右侧可直接修改科目名称、排序、启用状态、利润类型关联。
- `保存修改`：保存详情。
- `停用科目`：二次确认后停用。

弹窗：

- `CategoryFormModal`
- 标题根据场景变化：新增大类、新增小类、编辑科目。

与新版 PRD 差异：

- 现有系统有两级分类和启停。
- 尚未支持“二级分类需关联供应商”配置。
- 尚未支持历史分类名快照。

### 3.4 钉钉同步设置

页面：`app/ui/pages/dingtalk_settings.py`

主要区域：

- 配置状态条。
- 凭证配置卡片。
- 审批模板列表。

交互：

- 输入/保存 `appKey`、`appSecret`、可选 `admin_user_id`。
- `测试连接`：调用钉钉 OAuth2 获取 token 验证凭证。
- `刷新模板`：拉取可见审批模板并写入本地模板表。
- 模板筛选：分段按钮过滤模板范围。
- 选择模板后：
  - `启用同步 / 停用`
  - `配置字段映射`

安全交互：

- appKey 半遮罩回显。
- appSecret 全遮罩回显。
- 保存凭证后会清除旧 token 缓存。

### 3.5 字段映射配置

页面：`app/ui/pages/field_mapping.py`

用途：

- 将钉钉审批模板实际字段映射到系统标准字段。

交互：

- `返回钉钉同步设置` / `← 返回`：回到 `/dingtalk`。
- `从样例单获取实际字段`：调用钉钉接口取一张样例审批单，解析字段目录。
- 手动输入字段名后点 `添加`：加入可选字段列表。
- 每个标准字段选择一个实际字段。
- `保存映射`：保存到本地，并重解析该模板历史单据的 `raw_form_data`。

标准字段来自现有系统：

- 报销申请日期
- 支出详情
- 金额
- 出纳付款日期
- 其他备注
- 凭证图片
- 报销凭证文件

与新版 PRD 差异：

- 新版标准字段更多，包括门店、支出日期、申请人、凭证人、收款账户、分类等。
- 新版需要支持表格型审批单逐行解析为支出明细行；现有系统主要映射到报销单主表。

### 3.6 门店账套列表

页面：`app/ui/pages/workspace_list.py`

交互：

- 搜索门店名称。
- 列出所有门店卡片，包括停用门店。
- 卡片显示联系人、电话、账套数量、本月报销数量。
- 点击卡片：设置全局门店上下文，进入 `/workspace/{store_id}`。

注意：

- 当前文案里固定提示“8 月账套”，新版需要改成当前选择账期或默认上月。

### 3.7 门店账套首页

页面：`app/ui/pages/workspace_detail.py`

主要内容：

- 门店基础信息。
- 当前记账月。
- 四个业务入口卡片。

入口：

- 营业收入
- 审批单管理
- 银行流水
- 对账工作台

每个入口显示当月数据量或待办数，例如：

- 本月收入笔数与金额
- 本月报销单数与金额
- 本月流水数与待对账数
- 待对账流水数

与新版 PRD 差异：

- 新版要求六个子页面：账套首页、营业收入、银行流水、匹配工作台、单据管理、供应商列表。
- 现有系统没有供应商列表。
- 当前账期固定为 `current_period()`，不是“默认上一个月”。

### 3.8 营业收入

页面：`app/ui/pages/revenue.py`

主要区域：

- 收入渠道卡片网格。
- 当前选中渠道汇总条。
- 已录入明细表格。

交互：

- `+ 新增渠道`：打开新增渠道弹窗。
- 点击渠道卡片：选中渠道，展示明细。
- 点击卡片内 `录入`：打开逐日表格编辑器。
- 编辑器保存后刷新渠道卡片和明细。

明细列：

- 日期
- 金额
- 实收金额
- 手续费
- 费率
- 备注

编辑器：

- 使用 `RevenueTableEditor`。
- 支持逐日收入编辑。
- 保存时调用收入服务批量写入。

与新版 PRD 差异：

- 新版要求渠道配置“是否产生银行流水”，现有系统未体现。
- 新版要求 Excel 粘贴、起止日批量填充、未保存关闭确认，现有编辑器有部分表格能力，但需要重新核对覆盖范围。

### 3.9 审批单管理

页面：`app/ui/pages/reimbursements.py`

主要区域：

- 筛选栏。
- 汇总状态条。
- 报销单表格。
- 底部操作条。
- 同步进度条。

筛选项：

- 门店范围：当前门店、全部门店、待关联。
- 审批模板。
- 入账状态：全部、未入账、已入账。
- 搜索：详情/备注/单号。
- 申请日期起止。

操作：

- `查询`：刷新列表。
- `列设置`：调整可见列。
- `同步报销单`：启动增量同步。
- `核对近 90 天`：强制回溯窗口同步。
- `查看详情`：打开详情弹窗。
- 双击行：打开详情弹窗。
- `重新关联门店`：打开门店选择弹窗。
- `手动录入`：打开手动报销单弹窗。

同步交互：

- 同步运行时按钮进入 loading/禁用状态。
- 通过事件总线接收进度。
- 成功、部分成功、失败通过 Toast 和失败明细弹窗提示。
- 部分失败时提示“水位未推进”。

详情弹窗：

- 显示标准字段。
- 显示自定义字段。
- 显示凭证图片缩略图。
- 点击图片打开 `ImageViewer`。
- 钉盘附件权限不足时显示占位和“打开”入口。

与新版 PRD 差异：

- 当前叫“审批单管理”，新版应更偏“单据管理 + 支出明细行管理”。
- 当前没有归属账期调整。
- 当前没有明细行批量分类。
- 当前没有供应商关联。
- 当前没有审批状态作废后的联动解除提示。

### 3.10 银行流水

页面：`app/ui/pages/bank.py`

主要区域：

- 筛选栏。
- 汇总卡片。
- 操作栏。
- 流水表格。

筛选项：

- 日期范围。
- 方向：全部、进账、支出。
- 匹配状态：全部、未匹配、已匹配、部分匹配、已处理。

汇总：

- 收入合计。
- 支出合计。
- 净额。

操作：

- `+ 录入流水`：打开多行录入弹窗。
- `从 Excel 导入`：选择文件并导入。
- 双击行：编辑流水。
- 行操作/右键上下文：编辑、删除、标记无主流水等。
- 删除已匹配流水前需要先解除关联。
- 标记无主流水时需填写说明，可选择图片。

录入/编辑字段：

- 交易日期
- 金额
- 方向
- 备注

与新版 PRD 差异：

- 现有 Excel 导入要求固定列，不支持列映射预览。
- 没有导入批次。
- 没有指纹去重和整批撤销。
- 没有金额容差查询。

### 3.11 对账工作台

页面：`app/ui/pages/reconcile.py`

这是现有系统最核心的工作页面。

布局：

- 顶部：记账月选择、批量确认按钮、统计信息。
- 左侧：银行流水卡片列表。
- 右侧：当前流水的匹配建议和操作区。

顶部交互：

- 切换记账月：刷新当前门店该月流水与建议。
- `批量确认高置信匹配`：打开批量确认弹窗。
- 展示待匹配笔数、已匹配笔数、本月已入账金额。

左侧流水卡片：

- 显示日期、金额、方向、状态、摘要、关联摘要。
- 点击卡片选中流水。
- 未录入流水时提示先到银行流水页录入。

支出流水匹配：

- 系统推荐报销单候选。
- 候选显示置信度、推荐理由、金额、剩余待付等。
- 勾选候选后出现分摊金额输入。
- 实时显示分摊合计、流水金额和差额。
- `确认入账`：校验后写入关联。
- 支持一笔流水关联多张报销单。
- 支持多笔流水分期付清同一报销单。
- `手动关联...`：搜索并加入报销单建议。
- `不是这笔/拒绝建议`：后续不再推荐该组合。
- `查看详情`：打开报销单详情弹窗。

收入流水匹配：

- 选择收入渠道。
- 选择起止日期。
- 系统计算范围内收入合计，与流水金额比对。
- 可加入建议并确认。
- 已占用日期范围会被过滤/提示。

已匹配流水：

- 显示已关联对象。
- 可 `解除关联`，需二次确认。
- 解除后回退流水状态和报销单入账状态。

无匹配/留档：

- `标记为无匹配`。
- 填写说明。
- 可上传凭证文件。
- 提交后流水状态变为已处理。
- 已处理流水可“修改说明/重新匹配”。

批量确认：

- 系统生成高置信匹配计划。
- 打开 `BatchConfirmModal`。
- 用户确认后逐笔入账。
- 完成后 Toast 显示成功笔数。

与新版 PRD 差异：

- 当前匹配对象是报销单，不是支出明细行。
- 当前匹配限制同门店同月份。
- 当前差额校验要求完全等于流水金额，未实现新版 PRD 的尾差科目。
- 当前没有封账后禁止新增/解除匹配的全局约束。

### 3.13 财务报表

页面：`app/ui/pages/reports.py`

主要区域：

- 门店筛选。
- 月份筛选。
- 查询按钮。
- 导出按钮。
- 报表 Tab。
- 报表内容滚动区。

筛选：

- 门店：全部门店或单门店。
- 月份：从已有数据中提取。

Tab：

- 收支明细。
- 利润汇总。
- 分类汇总。

交互：

- 选择“全部门店”时隐藏单店 Tab，展示公司汇总。
- 单门店时显示三张报表 Tab。
- 点击收入记录：打开收入明细弹窗。
- 点击银行流水：打开银行流水详情弹窗。
- 在流水详情中点击关联报销单：打开报销单详情弹窗。

- 当前已有公司汇总，新版 PRD 阶段二暂不做跨门店对比。
- 当前报表口径仍按申请日期/报销单主表聚合，不是归属账期/支出明细行。

## 4. 弹窗与全局交互组件

### 4.1 通用弹窗

组件：`app/ui/components/modals.py`

- `Modal`：通用模态弹窗，居中、`transient`、`grab_set`。
- `ConfirmModal`：二次确认弹窗。

确认弹窗分级：

- `normal`：普通确认。
- `danger`：危险操作，例如删除、解除关联、停用。
- `warning`：有连锁影响的危险操作。

### 4.2 Toast

组件：`app/ui/components/toast.py`

- 位置：底部居中。

- 类型：`info`、`success`、`warn`、`error`。
- 通过 `EventBroker` 的 `app.toast` 事件触发。

### 4.3 部分成功结果条

## 5. 关键业务流程

### 5.1 首次配置钉钉

1. 进入“钉钉同步设置”。
2. 填写 `appKey/appSecret`。
3. 点击“保存凭证”。
4. 点击“测试连接”。
5. 点击“刷新模板”。
6. 选择财务相关模板。
7. 点击“配置字段映射”。
8. 从样例单获取字段或手动添加字段。
9. 保存字段映射。

### 5.2 做账流程

1. 进入“门店账套列表”。
2. 搜索并选择门店。
3. 进入门店账套首页。
4. 录入营业收入。
5. 同步或手动录入审批单。
6. 录入或导入银行流水。
7. 进入对账工作台。
8. 逐笔确认匹配。
9. 查看财务报表。
10. 导出 HTML 报表。

### 5.3 审批单同步流程

1. 在审批单管理页点击“同步报销单”。
2. 同步按钮进入 loading。
3. 进度条显示阶段和进度。
4. 成功后刷新列表。
5. 部分失败时显示失败明细，并提示水位未推进。
6. 可用“核对近 90 天”重新扫描。

### 5.4 对账确认流程

1. 选择一笔未匹配银行流水。
2. 查看右侧系统推荐。
3. 勾选一个或多个候选。
4. 调整分摊金额。
5. 系统校验差额。
6. 点击确认入账。
7. 系统写入关联，刷新流水状态和报销单入账状态。
8. 自动/手动切换到下一笔待匹配流水。

## 6. 对新版 Web 项目的参考价值

建议复用的交互模式：

- 左侧账套上下文 + 子页面入口。
- 对账工作台的左右分栏。
- 推荐候选卡片 + 勾选 + 分摊差额条。
- 同步/导出长任务进度条。
- 部分成功结果条。
- 凭证缩略图 + 大图查看器。
- 全局 Toast。
- 空态、搜索无结果、配置缺失横幅。

需要重做或升级的交互：

- 报销单管理应升级为“单据 + 支出明细行”。
- 字段映射应支持表格字段映射到明细行。
- 银行流水导入应支持列映射、预览、去重、批次撤销。
- 营业收入渠道应支持“是否产生银行流水”。
- 对账工作台应支持明细行级匹配、尾差科目、跨月匹配展示。
- 账套首页应支持封账、重开和写入状态提示。
- 新增供应商列表、供应商关联、应付汇总。
- 新增操作日志视图或至少关键操作审计入口。
