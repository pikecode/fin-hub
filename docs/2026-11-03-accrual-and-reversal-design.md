# 门店计提、补提与冲销设计

## 2026-11-05 最新调整：关联审批整单不入账

本节覆盖下文新建关联时的部分金额覆盖口径。新建计提关联无需输入覆盖金额，可一次选择多个审批单；一个原计提可关联多个审批单，同一审批单只允许一个有效整单关联，不能与部分覆盖混用。选择的审批整单不再计入费用报表，银行流水仍可对账，计提、补提和冲销照常按各自入账月份统计。审批合计超过计提金额也可关联，金额差异通过补提或冲销处理，不自动把差额再次列为审批费用。

后端新增 `AccrualApprovalLink.whole_approval`，迁移 `20261105_0042` 默认 false 保留历史部分覆盖口径，不自动变更既有报表。新接口 `/api/accruals/links/batch` 接收 original_id、approval_ids、remark、request_key 及分类差异确认，不接收金额，全部成功才提交；任一失败回滚整批。原单条接口不传 amount 时为整单关联，显式 amount 继续用于历史兼容及既有部分覆盖调用。

整单关联记录中的 amount 是关联当时审批总额快照，供审计展示，不是额度上限。报表排除审批实际全部入账明细，审批后续金额变化仍全额排除；原分类不改写。整单关联不占用部分覆盖可用额度，不限制通过补提 / 冲销核对金额；原计提及调整不得出现负有效金额等既有校验继续保留。存在关联时分类、删除及封账保护仍有效。

解除关联按原规则检查受影响审批入账月份是否封账，开放月份恢复正常审批费用；解除最后一笔银行对账时沿用原有自动释放关联行为。页面、HTML / PDF 和利润汇总沿用统一会计来源，整单排除不依赖银行付款金额。历史部分覆盖需先解除再以新方式关联，已封账月份不可直接转换。


## 需求与已确认决策

月初出具报表时，部分费用已经发生但审批或付款尚未完成，需要先确认费用。正式报表封账后，差额在后续开放账期调整；后续审批和实际付款不得重复确认已经计提的费用。

- 入口：具体门店“审批单对账”页面增加“计提与调整”页签。
- 计提选择门店、费用月份、二级费用分类、正金额，备注必填，不要求银行流水。
- 少计费用使用补提，多计费用使用冲销；均关联原计提，填写调整账期和原因，不覆盖原记录。
- 审批必须关联具体计提及覆盖金额，不能只勾选“已计提”；支持一笔计提对应多张审批、多笔计提覆盖一张审批。
- 正式出表以封账为准，导出 PDF/HTML 不自动封账。封账后只能后续账期调整，或按权限解封更正。
- 审批分类与计提不一致时明确提示，分类转移需在开放账期确认调整，不静默改写历史。

## 金额定义

### 后续月份补提 / 冲销操作（2026-11-04 更新）

原计提在 10 月、报表已封账时，可以将补提或冲销记入 11 月等后续开放账期。调整月份不要求等于原计提月份，必须不早于原计提月份。原账期保持原金额，本次调整只影响所选调整月份及其后累计数。

目标月份尚未创建账期时，弹窗显示账期状态，并提供“创建所选账期”按钮，沿用账期创建权限和审计；创建成功后再提交本次计提 / 调整。创建账期不等于已经保存补提，仍需点击确认。目标月份已封账则提示选择后续开放账期。查看月份已封账时，补提 / 冲销表单默认建议下一个月份。

跨月保存后明确提示实际入账月份，列表自动展示全部账期，避免当前月份过滤隐藏刚保存的后续月份记录。上述弹窗优化已开发验证，尚未部署生产。

原计提 65,000 元，后续确定应付 70,000 元：后续账期补提 5,000 元。若确定应付 60,000 元：后续账期冲销 5,000 元。真实付款金额可能分多次发生，不直接等同于最终应确认的费用。

- 计提有效金额＝原计提＋补提－冲销。
- 已覆盖金额＝所有有效审批关联覆盖金额之和，解除关联后释放额度。
- 可关联金额＝计提有效金额－已覆盖金额。
- 本月支出＝本月原计提＋补提－冲销＋未被计提覆盖的正常入账费用。
- 银行余额只由真实流水决定，计提和冲销都不产生银行流水。

审批关联与费用确认是不同维度：关联原计提不把原计提移到审批月份；审批匹配金额不等于当月新增费用。不得通过整单排除导致未覆盖部分漏算。

## 数据结构

### 计提台账 accrual_entries 与审计更正

字段：ID、门店、入账月份、类型（accrual/supplement/reversal）、原计提 ID、二级费用分类、金额、备注、创建人、创建时间、请求唯一键。

每条金额为正，冲销在查询统计中取负；补提和冲销必须指向同门店原计提，只能使用原计提月份及之后的月份。按 2026-11-04 确认的需求，未封账记录可通过专用入口编辑或删除，必须保留修改前后值和原因；封账记录不能直接改写。相同请求唯一键重复提交返回既有记录，参数不一致返回冲突。

原记录和调整事务串行锁定，累计冲销不得使有效金额小于零；后续接入审批覆盖时不得低于已覆盖金额。调整使用原分类；分类转移通过两笔关联的负向、正向调整实现，不直接修改历史分类。

### 审批覆盖 accrual_approval_links（第二阶段）

字段：ID、原计提 ID、审批 ID、覆盖金额、状态、确认账期、原因、操作者和时间。关联审批主单，覆盖额度按审批明细比例分配到分，不依赖某一条流水匹配，避免多笔付款重复扣减。

有有效对账时关联才能影响费用去重。最后一笔对账解除时，若影响已封账的费用则拒绝；允许解除时同步撤销覆盖并记录审计。已封账计提不能被“解除关联”间接改变。旧未实付虚拟流水不自动迁移，后续提供明确来源映射。

## API 与权限

- GET /api/accruals?store_id=&period=：门店账期台账，支持仅传门店查询全账期。
- POST /api/accruals：原计提或调整，服务端校验类别、月份、金额、备注、门店访问权、封账和重复请求。
- 后续：原计提详情、审批覆盖新增/解除、分类差异确认。
- 读取使用 reconciliation.view，写入使用 reconciliation.manage；每次写入审计。不暴露无权限门店记录。
- 金额使用 Decimal，保留两位小数；超精度、零、负数均拒绝。

## 页面与报表接入（第二阶段）

“计提与调整”展示原计提、补提、冲销、有效金额、审批已覆盖及待覆盖金额。表单按原计提/补提/冲销区分；冲销前展示可冲销额和受影响月份。提交中禁用重复操作，服务端唯一键提供最终幂等保障。

审批匹配弹窗展示原计提月份、分类、有效额度和本次覆盖金额；分类不同先提示，不自动变更分类。费用补提/冲销必须单独确认，不因为付款或审批导入自动调整。

统一接入门店总支出、分类统计、费用明细、分红累计利润、综合报表、HTML、PDF及流水附录；明细标记计提/补提/冲销及原计提编号。费用明细必须允许负数冲销，不能沿用 amount > 0 过滤。附录明确计提无银行流水，真实付款关联不能再次求和为费用。

## 2026-11-04 未封账记录编辑、删除与展示更新

- 页面默认展示全部账期，切换门店也恢复全部账期；保留当前账期筛选。
- 原计提、补提、冲销均增加编辑入口，可修改入账月份、金额、分类、备注，修改原因必填。`PATCH /api/accruals/{id}` 提交原字段快照 `expected`，服务端事务锁与原值对比阻止覆盖他人修改。创建人、原计提关联、类型与请求键不可改。
- 原月份与目标月份都必须已建立且开放；调整不能早于原计提；逐月累计金额不能因修改变成负数，有效金额不能低于审批已覆盖金额。金额修改涉及已封账审批覆盖时阻止。跨月更正同步更正对应费用记录，不影响不相关月份。
- 修改分类会统一更正原计提和同组补提 / 冲销，以保持同组口径一致；要求同组所有受影响月份均未封账且没有有效审批覆盖。已有覆盖时先核对解除，封账时使用后续调整。
- `DELETE /api/accruals/{id}` 必须提交 `expected` 和删除原因。台账与对应费用明细一起移除，完整原记录、请求键、原因、操作人和时间保存在审计中；同店同请求键的旧创建请求不能再次生成已删除费用。删除补提 / 冲销仍需满足每月可冲销额度、已覆盖额度和封账要求。
- 原计提存在补提 / 冲销时先处理调整记录；存在任何审批覆盖历史的原计提保留用于追溯，不允许删除，使用冲销更正。存在异常流水关联的计提费用也阻止删除。
- 专用编辑 / 删除沿用 `reconciliation.manage` 与门店权限；普通费用编辑仍不能改写计提明细。
- 财务报表费用详情增加计提 / 补提 / 冲销标签；原有金额统计继续按计提＋补提－冲销和实际审批覆盖计算。

## 2026-11-04 差额入账最终确认

审批实际金额超过计提覆盖金额时，未覆盖的差额正常计入审批入账月份，保留现有部分覆盖规则。例如原计提 65,000，审批 70,000，覆盖 65,000 时，审批入账月确认未覆盖的 5,000；如果已经手工补提且有效计提达到 70,000，应按实际情况确认覆盖额，避免重复确认差额。关联审批不代表不区分额度地排除整张审批。

报表中的手工银行卡余额是独立展示值，不改变计提、审批支出、银行流水或利润。入口在财务报表“资金流情况 → 录入报表余额”，按门店和月份保存原因及修改审计，封账后禁止修改。相关迁移为 `20261104_0041`，尚未部署。
