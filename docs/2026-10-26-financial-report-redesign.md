# 月度财务报表调整：需求复核、设计及实施计划

## 1. 范围与原则

依据 2026-10-26 报表调整图片和需求分析实施。统一 `/reports` 与门店内 `/store-ledgers/{storeId}/report`，共用视图、后端补充数据和 HTML/PDF 内容生成器。页面居中、最大宽度约 1120px，每行两至三项，不铺满宽屏。保留现有分类明细、图片预览、主要支出凭证。

本次不改变收入、支出分类和审批去重的既有财务规则；门店预充值、备用金/借款等排除逻辑继续生效。图外的同比、环比、净利率不再占据总览卡片。新增输入不会反向改写营业收入、审批费用或分红交易。

## 2. 页面结构

1. 门店营收：第一行营业收入、本月业绩目标、业绩完成率；第二行实收、手续费、手续费率，字号略小。
2. 门店支出：突出总支出；第二行营业毛利率、营运费用占比、薪资占比。百分比大字，下面明确标注对应食材成本、运营费用、人工成本金额。
3. 资金流情况：报表次月 10 日结束时银行余额，显示明确日期。12 月对应次年 1 月 10 日；未到日期显示待到期，无余额基准显示未录入，不以 0 冒充。
4. 利润分红：本月净利润（财务报表）、剩余未分配利润（分红管理）、本月分配利润、本月运营增资；随后筹建投入资金、筹建费用总支出、累计增资、累计分红。每行两至三项，不强行四列。
5. 营业收入渠道：横向分组条形图，营业收入、实收两组，按营业收入降序。
6. 核心成本率：仅食材、人工、租金，去掉运营费用一行。保留核心食材和分类数据。
7. 各类别支出统计：一级分类默认展开二级分类，仍可收起和查看凭证明细。

## 3. 数据定义及边界

- 业绩目标按门店、月份维护，未录入/0 时完成率为空，收入可以超过目标，不将数字截断至 100%。输入限非负金额，需管理员权限、门店权限、封账校验和审计。
- 毛利率＝（营业收入－食材成本）/营业收入；运营费用＝总支出－食材成本；薪资占比＝人工成本/营业收入。分母为 0 显示“—”。
- 次月 10 日余额：选择不晚于该日的最新余额校正，含校正当日以及截止日全部已实付/实收真实流水，排除未实付、未实收、已作废虚拟流水。不使用截止日之后的校正。历史数随历史数据更正重新计算，不伪装为锁定快照。
- 剩余未分配严格复用分红管理：2026-10 及以前人工输入，2026-11 起以 10 月余额为锚点递推；未录入的历史余额保持空值，不使用历史利润减分红替代。
- 本月运营增资＝原分红管理本月注资；累计运营增资只累计至所选月份，累计分红同理。
- 新增门店级筹建投入资金和可空的筹建费用总支出人工覆盖值，在分红管理维护；金额不计入利润。未录入筹建投入为 0；未录入筹建支出覆盖值回退筹建已确认审批原金额去重统计，明确录入 0 必须取 0。
- 筹建投入为门店当前设置值，属于门店资料而非每月新增交易，累计增资＝筹建投入＋截至该月累计运营增资。修改影响历史报表展示，保存留痕；界面需说明此性质。
- 读取补充报表数据不能创建分红月份、账套或其他业务数据。

## 4. 导出与流水附录

HTML 和 PDF 使用同一生成内容，A4 纵向，统一字体、边距、分组及分页，PDF 直接下载。数据不因当前列表分页而截断，不采用 500 条固定上限。

前部为上述报表数据、渠道及分类统计、支出明细、主要支出凭证。后部新增流水业务附录：

- 普通支出以已确认审批对账的入账月归属；收入以已确认收入关联的入账月归属，不按银行发生月过滤。
- 同一流水关联多个入账月，出现在每个相关月的附录；在同一月按流水 ID 合并，列出本月关联业务。
- 特殊属性及直接入账流水按发生月进入，排除已作废虚拟流水。筹建对账不混入日常月报附录。
- 未实付核对完成后，以真实付款代替原作废登记；多笔付款均可追溯原审批，保留整组审批金额说明，不按比例拆费用、不把重复列示的审批金额再次求和。
- 列出发生日期、收支类型、对方户名、流水金额、流水属性、关联业务（报销内容、申请日期、分类、确认入账金额；收入日期；特殊流水备注）。流水总金额与审批入账金额是两种口径，不计算附录合计并冒充报表支出。

## 6. 实际实现

- 新增迁移 `20261026_0034`：`financial_report_month_settings` 按门店、月份保存业绩目标；`dividend_funding_settings` 保存门店筹建投入和可空的支出覆盖值。
- `GET /api/reports/financial-supplement` 只读汇总目标、截止日余额、分红历史口径和筹建资料，不创建月份和账套。
- `PATCH /api/reports/financial-target` 维护目标，支持清空，校验管理员、门店权限、封账并留痕。
- `GET/PATCH /api/dividends/stores/{store_id}/funding-settings` 对应分红管理“筹建资金资料”入口。
- `GET /api/reports/financial-appendix` 返回完整业务流水和费用，支持跨月对账、收入日期、特殊备注、直接入账和已完成未实付核对后的真实付款。
- 报表两个入口共用 `StoreFinancialReportView`；页面和导出共用 `reportGroups`，HTML/PDF 共用 `financialReportHtml`。渠道图按营业收入降序、两组横向条形显示，费用分类默认展开。
- PDF 采用 A4 纵向，先按实际 DOM 高度分页，再逐页生成画布，附录续页重复表头，避免超长单画布导致空白。极长单条业务仍保留内容，必要时缩放至单页。
- 复核时修复了银行直接入账费用在门店月报和分红累计净利计算中的遗漏，与综合报表及新导出统一；新增回归验证。

## 审批单多账期入账（2026-10-27）

### 需求与交互

- 审批单确认匹配、已对账记录编辑中增加“分多个账期入账”开关。默认关闭，保持原单一入账月份操作；开启后可添加月份和对应金额，至少两个月份，月份使用中文选择器。
- 每个月份不可重复，金额必须大于 0，各月金额合计必须等于完整审批单总额。示例：审批 60,000 元，9、10、11 月各 20,000 元，相应月份报表各统计 20,000 元。
- 再次打开时回填已经保存的月份和金额。关闭已有多账期开关，需要将审批单全部金额明确转入选中的单一月份。
- 审批明细和入账方案加载期间禁用确认；加载失败和保存失败在弹窗内提示，防止无响应及旧请求覆盖新弹窗。

### 统计口径与约束

- 入账方案以审批单为单位保存，银行匹配金额仍表示实际关联流水金额。一个审批关联多笔银行流水时，分月费用只统计一次。
- 各月分类金额按原审批明细金额比例分配，按分处理尾差，保证每月合计及每条明细跨月合计均准确。原审批金额和申请日期不被改写。
- 各类别统计、费用详情、报表净利润、分红所用报表利润和导出附录采用相同分月金额；门店预充值、备用金/借款等排除规则继续生效。
- 最后一笔确认匹配解除后，审批费用不再计入报表，入账方案保留便于后续回填。修改方案影响所有关联流水，界面明确提示。
- 修改、解除匹配需检查新旧方案所有受影响月份是否封账，并记录审计。方案版本防止旧弹窗覆盖新方案；已匹配的原始金额不能直接修改，封账后的分类也不能绕过限制修改。
- 未开启过分月方案的审批继续使用既有单账期规则；筹建审批不使用此入口。

### 实施与验证

- 新增审批级方案及月份金额表，迁移 `20261027_0036` 依赖 0035；后端确认匹配时发布方案，候选匹配不提前改变报表。
