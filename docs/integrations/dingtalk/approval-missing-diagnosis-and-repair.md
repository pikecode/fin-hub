# 钉钉审批漏数诊断与修复方案

日期：2026-09-08

## 问题背景

用户提供了一批审批单号，用来核对“为什么这批审批看起来没有同步进来”。
这批单号只是诊断样本，不是同步范围标准。

## 结论

审批单漏数通常不是单号本身的问题，而是下面三类之一：

1. 同步窗口过窄，导致历史审批没有被扫到。
2. 审批已经入库，但被页面默认过滤掉了，例如默认隐藏已匹配。
3. 审批已入库，但处于 `unparsed` / `pending_match` / `sync_conflict` 等后处理状态，用户误以为没同步。

## 处理原则

1. 手动同步按当前启用模板全量扫描，不再限制天数。
2. 审批列表默认展示已匹配和未匹配，不再只看未匹配。
3. 增加按审批号诊断接口，批量确认这些单号在库中是什么状态。
4. 对 `unparsed` 和可重跑的审批，提供批量重解析入口。

## 预期结果

- 用户可以直接确认某个审批号是否存在。
- 如果已存在，可以看到它是已匹配、未匹配还是未解析。
- 如果确实是未解析，可以触发重解析修复，而不是继续扩大同步窗口。


## 2026-11-05 门店落库异常筛选

入口：钉钉同步 → 审批列表 → “全部门店关联状态”切换为“门店落库异常”。可叠加当前落库门店、模板、关键词和审批状态；先筛选再分页，符合条件总数是异常审批数。关联门店列显示具体原因，点击“更正门店”处理；成功后重新查询，已消除异常的记录会退出筛选结果。

检查范围包括未关联有效门店、审批与费用明细门店不同、人工指定门店与落库门店不同、表单来源门店无法识别，以及原有解析规则可识别的来源门店与落库门店不同。沿用模板映射和门店 / 部门解析规则；明确表单门店无法识别时显示待核对，不把申请人所属部门当成已确认的正确门店。人工更正记录以人工指定门店为准，不因原表单不同反复误报。

此筛选只读，不调用钉钉、不重解析、不修改审批、费用、流水和报表。仍沿用管理员更正及已匹配 / 封账保护。筛选是在现有启用模板范围内检测，不推断缺少来源证据的任意错误门店；人工确认的错误目标也需要人工判断。关闭异常筛选后恢复普通列表。无需数据库迁移，尚未部署生产。
