## 自动同步

依附现有自动同步任务及启用模板，不新增独立定时任务。

| 单据情况 | 复查资格 |
| --- | --- |
| 审批中等流转状态 | 每轮可刷新 |
| 撤回、拒绝、近期完成及解析异常 | 距上次解析至少24小时后可刷新 |
| 完成超过30天、解析正常的历史单 | 距上次解析至少7天后可刷新 |
| 已确认入账或有效计提关联 | 每日监测资格 |

除同步窗口内的发现流程外，额外按本地审批ID补查窗口外旧单。历史补查每轮最多100张，已入账监测补查每轮最多100张，均优先选择最久未检查的单据，避免固定ID次序造成饥饿。批量积压时需多轮消化，7天是进入复查队列的间隔，不承诺所有历史审批在7天内必定完成复查。无来源的审批记录检查时间，避免反复挤占下一轮预算。任务摘要记录历史预算和选中数。

钉钉新生成的审批实例仍通过已有按模板拉取发现；原单与新单不能仅凭相同单号或金额推断为同一单，沿用显式修订关系及人工历史核对规则。

## 匹配前实时校验

真实钉钉模式下，创建费用匹配候选、确认候选和编辑已对账记录，均在财务修改之前读取最新审批详情。手工费用及测试模拟模式不联网。

1. 先完成用户、门店和操作权限检查，再读取钉钉；完整性与实例ID异常均拒绝本次操作。
2. 比较状态、表单、单号、标题及修订关系等业务快照；忽略仅任务流转和修改时间等无业务变化的字段。
3. 有变化时使用现有同步解析逻辑更新来源，独立保存同步结果和审计，返回409要求刷新；不会同时提交本次匹配、分类或入账月份修改。
4. 无变化时仍要求审批已通过、解析有效且无费用来源冲突。退回及未知流程状态优先于旧的通过结果，不会因残留的agree结果被当成已通过。确认前重新锁定并读取候选状态，已作废的缓存候选不能继续确认。
5. 钉钉请求失败、超时、权限/配置异常或返回详情不完整时返回503，本次匹配不确认。交互校验单次HTTP超时5秒，不进行限流等待；令牌失效保留原有一次刷新重试，整体请求可能包含多次HTTP调用，不承诺总耗时为5秒。后台同步继续使用原有重试机制。

已确认记录的重复确认仍按原接口幂等返回，不重新确认或改写账目。需要财务纠正的历史冲突，可按原流程解除匹配后重新同步、核对及匹配；封账约束仍生效。
