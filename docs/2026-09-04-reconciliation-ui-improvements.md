# 对账匹配界面优化

**日期**: 2026-09-04  
**修改范围**: 审批单对账 - 匹配并分类对话框  
**文件**: `apps/admin-web/app/finance/reconciliation/page.tsx`

---

## 修改内容

### 1. 入账月份 - 去掉默认值

**修改位置**: `openConfirm` 函数 (第 562 行)

**修改前**:
```tsx
confirmForm.setFieldsValue({
  amount: defaultMatchAmount.toFixed(2),
  accounting_month: dayjs(selectedLedgerPeriod), // 自动填充为当前账期
  bank_occurred: true,
  category_path: categoryPathForName(selectedCandidate.expense_item.category_l2),
});
```

**修改后**:
```tsx
confirmForm.setFieldsValue({
  amount: defaultMatchAmount.toFixed(2),
  accounting_month: undefined, // 去掉默认值，用户必须手动选择
  bank_occurred: true,
  category_path: categoryPathForName(selectedCandidate.expense_item.category_l2),
});
```

**原因**:
- 入账月份是重要的会计决策，不应该自动填充
- 强制用户明确选择，避免遗忘修改导致错误入账
- 特别是跨期对账场景，需要用户仔细考虑

**用户体验**:
- ✅ 打开对话框时，入账月份为空
- ✅ 必须手动选择后才能提交（required 验证）
- ✅ 增加了一个操作步骤，但提高了准确性

**表单验证增强** (第 1145 行):
```tsx
<Form.Item name="accounting_month" label="入账月份" rules={[{ required: true, message: "请选择入账月份" }]}>
  <DatePicker picker="month" placeholder="请选择入账月份" style={{ width: "100%" }} />
</Form.Item>
```

- 添加了明确的错误提示：`"请选择入账月份"`
- 添加了占位符：`"请选择入账月份"`

---

### 2. 匹配金额 - 禁止修改

**修改位置**: 表单字段定义 (第 1148-1150 行)

**修改前**:
```tsx
<Form.Item name="amount" label="匹配金额" rules={[{ required: true, message: "请输入匹配金额" }]}>
  <Input />
</Form.Item>
```

**修改后**:
```tsx
<Form.Item name="amount" label="匹配金额" rules={[{ required: true, message: "请输入匹配金额" }]}>
  <Input disabled />
</Form.Item>
```

**原因**:
- 匹配金额由系统自动计算，确保数据一致性
- 计算逻辑：`Math.min(bankRemaining, expenseRemaining)`
  - 取银行流水剩余金额和审批单剩余金额的较小值
- 避免用户手动输入导致金额错误

**计算逻辑** (第 287-288 行):
```tsx
const bankRemaining = selectedTransaction ? remainingAmount(selectedTransaction) : 0;
const defaultMatchAmount = selectedCandidate 
  ? Math.min(bankRemaining, Number(selectedCandidate.remaining_amount || 0)) 
  : bankRemaining;
```

**用户体验**:
- ✅ 金额字段显示为灰色（disabled 状态）
- ✅ 自动计算的金额清晰展示
- ✅ 用户无法修改，避免错误输入
- ✅ 简化操作流程

## 使用流程变化

### 修改前的流程

1. 选择银行流水
2. 选择审批单
3. 点击"确认匹配"
4. 对话框打开，入账月份**已自动填充**
5. 检查金额（可以修改）
6. 选择费用分类
7. 点击"确认匹配"

**问题**:
- 用户可能忘记检查入账月份，直接提交
- 用户可能误修改匹配金额，导致数据错误

### 修改后的流程

1. 选择银行流水
2. 选择审批单
3. 点击"确认匹配"
4. 对话框打开，入账月份**为空**
5. **必须手动选择入账月份** ← 新增步骤
6. 检查金额（自动计算，不可修改）
7. 选择费用分类
8. 点击"确认匹配"

**改进**:
- ✅ 强制用户明确选择入账月份
- ✅ 避免金额被误修改
- ✅ 提高数据准确性

## 业务场景说明

### 场景 1: 同期对账

```
操作:
1. 选择 8月银行流水（账期 2026-08）
2. 选择对应的审批单
3. 打开对话框 → 入账月份为空
4. 手动选择 2026-08
5. 匹配金额自动显示 1000.00（禁止修改）
6. 确认匹配

结果:
- 入账月份: 2026-08（与流水账期一致）
- 匹配金额: 1000.00（系统自动计算）
```

### 场景 2: 跨期对账

```
操作:
1. 选择 8月银行流水（账期 2026-08）
2. 选择对应的审批单
3. 打开对话框 → 入账月份为空
4. 用户思考后，手动选择 2026-09（延迟入账）
5. 匹配金额自动显示 1000.00（禁止修改）
6. 确认匹配

结果:
- 入账月份: 2026-09（跨期入账）
- 匹配金额: 1000.00（系统自动计算）

优点:
- 用户必须明确做出跨期决策
- 不会因为默认值而忘记修改
```

### 场景 3: 部分匹配

```
情况:
- 银行流水剩余金额: 3000.00
- 审批单剩余金额: 1000.00

操作:
1. 选择银行流水
2. 选择审批单
3. 打开对话框
4. 匹配金额自动显示 1000.00（取较小值）
5. 用户无法修改为 3000.00（禁止修改）
6. 选择入账月份
7. 确认匹配

结果:
- 匹配金额: 1000.00（正确）
- 银行流水剩余: 2000.00（可继续匹配其他审批单）

优点:
- 避免用户误输入 3000.00
- 确保金额计算正确
```

## 用户培训要点

### 给财务人员的说明

**变化 1: 入账月份必须手动选择**

> "从现在开始，在匹配银行流水和审批单时，系统不再自动填写入账月份。您需要根据会计准则，明确选择费用应该计入哪个月的账期。"

**操作建议**:
- 大部分情况下，选择与银行流水相同的月份
- 跨月费用（如月初扣款的上月费用）需要选择正确的会计月份
- 延迟入账的费用按实际发生月份选择

**变化 2: 匹配金额不能修改**

> "匹配金额由系统自动计算，确保不会超过银行流水或审批单的剩余金额。您不再需要（也不能）手动输入匹配金额。"

**计算规则**:
- 取银行流水剩余金额和审批单剩余金额的较小值
- 确保一对一或一对多匹配时金额正确
- 避免超额匹配
