# 修改记录规范

项目中的每次代码修改、配置调整、功能完善、部署发布和运维变更，都必须记录到[项目修改记录](../CHANGELOG.md)。复杂方案、部署手册和长期操作流程才单独创建文档，并在总记录中关联。

## 排序规则

- 按日期倒序，最新日期在前。
- 同一天按时间倒序，最新记录在前。
- 新记录插入文档顶部，不追加到末尾。
- 时间统一使用 `Asia/Shanghai` 时区。

## 必填字段

每条记录必须包含：

- 时间：`YYYY-MM-DD HH:mm`
- 耗时：从开始检查或编辑到验证完成；不能留空
- 类型：功能、修复、优化、部署或运维，可组合
- 内容：修改内容、修改原因和影响范围
- 验证：实际执行的命令、测试、构建或线上验收结果
- 结果：已完成、已部署、未部署、部分完成或被阻塞
- 回滚或注意事项：回滚方式、数据库迁移状态、已知限制

## 推荐格式

```markdown
## YYYY-MM-DD

### 修改名称

- 时间：YYYY-MM-DD HH:mm（Asia/Shanghai）
- 耗时：约 X 分钟
- 类型：功能 / 修复 / 优化 / 部署 / 运维
- 内容：修改了什么；为什么修改；影响范围
- 验证：执行的命令、测试或线上验收；结果
- 结果：已完成 / 已部署 / 未部署 / 部分完成 / 被阻塞
- 回滚或注意事项：回滚方式、迁移状态和已知限制
- 关联文档：可选
```

## 记录边界

- 只记录事实，不写无法验证的推测。
- 测试失败必须记录失败命令、失败数量和是否与本次修改相关。
- 部署记录必须包含环境、服务、版本或镜像标签、数据库迁移状态和回滚方式。
- 不记录密码、令牌、生产数据库连接串等敏感信息，只记录脱敏后的环境或资源标识。
- 旧记录保留，不修改历史事实；如需更正，在顶部新增更正记录并关联原记录。
