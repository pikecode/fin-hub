# 多明细计提单、审批明细关联与图片凭证

时间：2026-11-09 11:12（Asia/Shanghai）；2026-11-10 更新。状态：已实现，完成接口回归与浏览器基础流程验证，未部署。

本设计补充 `2026-11-03-accrual-and-reversal-design.md`；新需求涉及关联粒度变化，旧整单关联和历史金额覆盖记录继续兼容，不自动转换。

## 需求

- 一张计提单支持多条费用，各行独立选择二级分类、金额、费用说明；单据归属一个门店和入账月份，自动汇总总额。
- 一个计提单可关联多张审批；一张审批的不同明细可关联不同计提单。
- 关联时可选整单或勾选一个、多个明细，不要求填写覆盖金额。
- 计提支持多张图片凭证，财务报表对应费用明细可以点击查看。

## 关联和入账规则

1. 整单模式沿用当前规则：审批全部费用不重复进入报表，包括后续新增明细；发生变更必须出现醒目核对提醒。
2. 明细模式仅排除已选审批明细的实际入账金额，未选明细按原规则正常入账；新增审批明细不自动继承排除状态。
3. 同一审批允许不同明细关联不同计提单；同一明细仅允许一个有效归属。存在整单关联时不能再绑定明细，存在明细关联时也不能直接整单关联，必须先明确解除。
4. 关联界面左侧选择计提费用行，右侧勾选审批费用行。同一计提行可绑定多个审批明细；多分类计提可分行建立映射。禁止仅靠分类名称或金额推断绑定。
5. 审批分类不同于计提分类时提示并要求确认；不回写已封账计提。审批实际金额与计提有效额可有差异，显示差额，由后续开放月份补提或冲销调整，不自动修改历史报表。
6. 补提、冲销关联具体原计提行；原计提单总额为各行汇总。原有防负额、权限、封账、幂等和审计规则保留。
7. 审批仍可正常与银行流水对账；关联计提仅影响费用重复确认，不占用银行匹配额度，不修改实际银行余额。
8. 涉及已封账报表的关联或解除不能直接改变历史金额；提示按现有解封或后期调整流程处理。

## 数据与兼容

新增计提单表，存门店、月份、说明、编号、创建人、时间、版本及幂等键。复用 accrual_entries 作为分类费用行，增加可空单据 ID；补提、冲销继续指向原费用行。旧记录展示为单明细计提，不改变原 ID、金额、分类和关联。

关联记录增加明细模式和绑定明细实体，保存审批 ID、费用 ID、稳定的审批行标识及关联时分类/金额/内容快照。不能将旧 whole_approval=false 的金额覆盖记录视为明细关联。新批量保存必须事务化、锁定审批及计提，防止并发重复占用明细。

审批同步发生变动时纳入变更提醒；计提关联的审批也纳入定时复核，关键金额/门店/月份不静默覆盖。保存费用 ID 和稳定行标识快照；若删除或重建费用 ID，报表明确提示核对并重新关联，不自动猜测归属。已封账报表保持保护。

报表去重在统一计提会计计算层执行，按选中明细及其各月实际入账分配额排除；整单、历史金额覆盖、明细模式分支明确。月报、分类累计、利润分红及导出使用同一口径。

## 凭证

本版复用计提行镜像费用的 expense_item 附件：保存计提单后为各费用行上传 PNG/JPEG 图片，单张不超过 500KB。上传校验图片签名、大小、门店授权和封账；预览/下载同样校验授权。每行独立保存，报表对应项目直接查看。本版没有单据共享凭证和附件删除入口。

报表费用明细通过计提来源 ID 展示凭证入口，点击查看图片。HTML 可提供需登录的受控预览入口；PDF 为静态文件，应展示凭证缩略图或凭证附页及引用编号，不写入会过期的临时访问令牌。封账后的附件变更需遵循审计及封账规则。

## 实施顺序及验收

1. 数据迁移、计提单批量创建及多行表单，兼容旧记录；一行失败整体回滚。
2. 审批明细选择、互斥校验、绑定/解除、同步变更提醒和会计去重。
3. 图片上传、报表明细查看、HTML/PDF 展示。
4. PostgreSQL 回归与浏览器及实际 PDF 验收，再按部署文档发布。

验收至少包含：同单多分类；同审批不同明细归属不同计提；重复绑定与并发拒绝；整单和明细互斥；未绑定明细正常入账；跨月分摊不重复排除；补提/冲销不修改原月；审批修改/删除/重同步提醒；旧整单与部分金额覆盖回归；附件跨门店访问拒绝；页面、导出和分类累计金额一致。

## 本版操作与验证（2026-11-10）

- 审批单对账 → 计提与调整 → 新增计提单（多明细），各行选分类/金额/说明，整体事务保存；保存后上传行凭证。列表按计提单编号识别同单费用，各行独立补提/冲销、编辑及关联审批。
- 关联审批 → 关联范围选择整张或勾选明细；已关联明细禁选，后台再次互斥校验。不同计提行可分别绑定同一审批不同明细；多行映射逐行提交，不自动按金额分类配对。
- HTML/PDF 附加计提与借还款凭证图片，不依赖临时链接。页面费用明细、计提费用区均支持查看。
- 新增 0046 保存明细选择快照，兼容旧整单及历史金额覆盖；0044 的计提单主表继续复用。
- PostgreSQL 相关回归总计 81 项通过；浏览器完成两分类计提 800+200 保存及凭证入口验证。开发模式发现原对账页“编辑主要支出凭证” forceRender 弹窗存在 hydration 警告，未阻断保存；此警告未在本批处理，不宣称控制台无警告。
