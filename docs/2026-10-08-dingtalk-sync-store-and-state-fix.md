# 钉钉同步门店归属与状态修复

## 问题与设计

自动同步正常执行，部分审批已拉取，但门店归属解析失败，或自动应用源数据后仍显示来源变化冲突。

1. 门店字段补充“报销门店”别名，解析预览和正式同步共用相同识别规则。
2. 使用部门 ID、完整路径定位部门，并沿 parent_id 向上查找所属门店；重复子部门名称只有最终归属唯一时才返回门店，循环部门链安全终止，不根据总部或区域名称猜测门店。
3. 来源变化只有遇到无法覆盖的字段差异时才显示冲突；普通可更新字段自动应用后恢复正常。人工修改仍受保护，源字段未变化时不将人工差异新标记为同步冲突；已匹配金额、门店、账期继续受保护，真实金额冲突持续保留。
4. 将历史审批补录任务纳入中断恢复，仍受数据库执行锁保护，避免把正在执行的任务判为中断。

## 验证

隔离 PostgreSQL 测试库执行门店解析、同步恢复、同步优化三个测试文件，34项通过。新增覆盖报销门店别名、子部门归属、同名部门歧义、来源变化恢复、人工编辑保护、已匹配金额保护和历史补录中断恢复。

## 第二阶段：人工分类误报与无效审批状态收尾

逐条读取剩余审批原始表单和部门链，确认启用门店候选部门均已关联门店；未关联记录的支出门店实际填写采购部、财务部、公司或区域部门，未发现这些记录由门店漏同步或改名造成。其中20条为撤销或拒绝，只有3条已通过且需要业务确认具体归属。

进一步对279条来源变化费用行逐字段比对当前值与来源快照：277条仅一级、二级分类不同，2条仅一级分类不同；其他快照字段均一致，且人工编辑字段均为分类。因此这些状态是人工分类误报，不代表门店或金额同步异常。

### 后续同步规则

人工维护的 category_l1、category_l2、preopening_category_id 属于本地分类决策，保持用户编辑保护，不因不同于钉钉原始分类而产生同步冲突。其他受保护字段和已匹配金额差异继续进行冲突检测。
