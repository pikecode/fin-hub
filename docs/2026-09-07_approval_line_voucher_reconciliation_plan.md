# 审批单明细与报销凭证对齐方案

## 背景

当前钉钉审批同步时，审批单的表格明细会被拆成多条 `expense_item`，但报销凭证仍然按审批单级统一挂载。
结果是：
- 确认匹配页的多条明细共用同一批凭证
- 查看明细时也会出现“凭证显示到一起”的现象
- 用户无法直观看到“哪条明细对应哪张凭证”

## 问题根因

现有同步逻辑里：
- 明细行是按表格逐行拆分的
- `voucher_items` 是在审批单级统一收集的
- 创建每条 `expense_item` 时，又把同一批 `voucher_items` 全部挂到了这条明细上

这导致凭证粒度比明细粒度粗，前端无法按行精确展示。

## 目标

1. 明细和凭证按同一粒度管理
2. 确认匹配时，每个明细只展示自己的凭证
3. 查看明细时，展示方式与表格单元格预览一致
4. 兼容没有行级凭证的历史审批单

## 方案

### 1. 同步模型调整

同步审批单时，按优先级处理凭证来源：

1. 表格明细行里的凭证字段
2. 审批单表单里的凭证字段
3. 审批单级兜底凭证

最终目标是为每条 `expense_item` 生成自己的附件集合。

### 2. 数据绑定方式

新增或调整规则：
- 每个 `expense_item` 只关联自己的附件
- 附件资源仍然使用 `resource_type=expense_item`
- 行级没有凭证时，才使用审批单级兜底附件

### 3. 前端展示方式

确认匹配页和查看明细页都改成：
- 只读取当前 `expense_item` 的附件
- 直接使用预览渲染
- 不再把整单附件汇总后展示

### 4. 旧数据处理

历史数据不直接假设能自动恢复正确关系，建议采用“重建模式”：

1. 删除受影响审批单的派生数据
   - `expense_items`
   - `attachments`
   - `expense_bank_matches`
   - 相关审批同步日志
2. 保留源数据
   - `approval_instances`
   - 模板
   - 部门
   - 门店
3. 用新同步逻辑重新生成这些审批单

建议范围：
- 先按门店
- 再按账期
- 必要时按审批编号定点重建

## 实施顺序

1. 先改同步逻辑，补齐行级凭证绑定
2. 再改前端展示，只显示当前明细自己的凭证
3. 再对受影响数据做重建和重同步
4. 最后补一轮回归验证

## 风险

- 历史数据如果不清理，旧附件会继续干扰展示
- 如果审批模板里没有稳定的行级凭证字段，只能退回到审批单级兜底
- 需要确认哪些模板支持行级凭证，哪些只能走整单兜底

## 验证点

- 同一审批单的多条明细不会共用同一批凭证
- 确认匹配页每行只显示自己的附件
- 查看明细页和确认匹配页的凭证显示一致
- 历史已匹配数据不被误改
