# 审批单明细与对账设计开发文档

## 背景

门店套帐中的审批单不是单纯的钉钉同步记录。财务做账时需要处理审批单中的费用明细，给不同明细设置费用分类、供应商、账期，并把明细与一笔或多笔银行流水做付款对账。

## 设计结论

审批单主数据、费用明细、银行流水匹配必须分层。

```text
approval_instances 1:N expense_items
expense_items N:M bank_transactions
```

不建议把分类、匹配状态、银行流水 ID 直接堆到 `approval_instances` 上。审批单是一张业务单据，真正参与入账和对账的是审批单下的费用明细。

## 钉钉截图样本观察

本轮参考的钉钉审批详情截图覆盖了几类典型单据：

- 门店支出报销，包含明细表：支出详情、小项金额、报销凭证。
- 门店支出报销，整单金额，没有明细表。
- 员工工资，通常包含明细表和考勤/工资附件。
- 门店筹建报销，可能包含分期付款字段：首期费用、第二期费用、第三期费用。
- 报销凭证既可能是图片，也可能是 Excel/文档附件。
- 收款账户是结构化信息：收款人、账户类型、银行、开户地、银行卡号、校验结果。
- 审批流里有发起人、人事审批、财务审批、退回、重新发起、抄送等节点。

这些样本说明：费用明细来源不能只理解为钉钉表格行，还要支持整单和分期字段拆分。

## 数据职责

### approval_instances

保存钉钉审批实例事实。

- 钉钉审批实例 ID
- 审批编号
- 审批模板
- 申请人
- 部门
- 审批状态
- 提交时间、完成时间
- 原始 `raw_payload`
- 同步任务 ID

### expense_items

保存财务做账费用明细。

- 归属门店
- 归属账期
- 费用日期
- 摘要
- 金额
- 一级分类、二级分类
- 供应商
- 收款账户
- 来源审批单
- 来源审批单明细行
- 付款状态
- 解析状态
- 备注

后续建议补强收款账户结构化字段，避免长期只依赖 `payee_account` 文本：

- `payee_name`
- `payee_bank_name`
- `payee_bank_branch`
- `payee_account_no`
- `payee_account_type`
- `payee_account_verify_status`
- `payee_account_snapshot_json`

截图中收款账户存在“校验通过”和“校验提示/不一致”的状态，这会影响付款对账风险提示。

### expense_bank_matches

保存费用明细与银行流水的匹配关系。

- 费用明细 ID
- 银行流水 ID
- 匹配金额
- 匹配状态
- 会计账期
- 银行是否实际发生

## 明细解析规则

1. 钉钉审批单有明细表时，一行明细生成一条 `expense_items`。
2. 钉钉审批单没有明细表时，整单生成一条 `expense_items`。
3. 钉钉审批单有分期付款字段时，可以按付款期次生成多条 `expense_items` 或生成付款计划，具体取决于是否需要按期次对账。
4. 每条费用明细保留 `approval_instance_id`、`approval_line_no`、`approval_line_key`。
5. 重复同步时按 `source_document_id` 幂等，不重复创建费用明细。
6. 已发生银行匹配的费用明细不能被同步任务自动删除。

### 明细来源类型

建议增加 `approval_line_source_type` 或在 `source_snapshot_json` 中保存来源类型：

- `table_row`：来自钉钉明细表的一行。
- `whole_approval`：来自整张审批单。
- `installment`：来自首期、第二期、第三期等分期字段。
- `manual_split`：财务人员手工拆分。

### 分期付款处理建议

截图中的“是否分期付款、首期费用、第二期费用、第三期费用”不应简单压成整单一条费用。建议按业务选择两阶段设计：

M1 可以先把整单作为一条费用，同时把分期字段保存到 `source_snapshot_json`，并标记 `parse_status=parsed_with_installments`。

M2 再增加付款计划表：

```text
expense_payment_schedules
- expense_item_id
- installment_no
- planned_amount
- planned_period
- matched_amount
- status
```

如果财务要求按每期独立匹配银行流水，也可以直接将分期拆成多条 `expense_items`，但要保留同一个 `approval_instance_id` 和明确的 `approval_line_key`。

### 附件归属

截图中附件有两层：

- 审批单级附件：报销凭证文档、Excel、整单图片。
- 明细行级附件：明细表每行的报销凭证图片。

建议继续使用统一 `attachments` 表，但资源类型要区分：

```text
approval_instance
expense_item
```

同步时审批单级附件挂到 `approval_instance`，明细行凭证挂到对应 `expense_item`。

### 审批流信息

当前 `approval_instances.raw_payload` 会保存原始审批流，但产品上需要可读摘要：

- 发起人
- 当前审批状态
- 当前待处理人
- 最近退回原因
- 财务审批意见
- 完成时间

这些信息可以先从 `raw_payload` 动态解析展示，后续再按性能需要增加 `approval_timeline_snapshot_json`。

## 审批单状态聚合

审批单整体状态不直接存死，优先由明细和匹配关系聚合得到。

- 未解析：没有生成费用明细
- 待分类：存在未分类费用明细
- 待匹配：存在未付款费用明细
- 部分匹配：部分费用明细已匹配
- 已匹配：所有费用明细已付款
- 异常：匹配金额超过审批金额或关键字段缺失

## 产品交互

### 审批单列表

字段建议：

- 审批编号
- 申请人
- 部门
- 审批状态
- 审批金额
- 明细数
- 已分类数
- 已匹配金额
- 未匹配金额
- 处理状态

### 审批单详情

采用主从结构：

```text
审批单摘要
费用明细表
关联银行流水
附件与凭证
收款账户
审批流
原始钉钉数据
```

费用明细表支持：

- 查看分类状态
- 修改供应商
- 修改账期
- 修改备注
- 拆分明细
- 忽略明细
- 跳转到对账工作台匹配银行流水

说明：分类主流程不放在审批单详情里完成。审批单详情主要用于回看钉钉原单、附件、收款账户和明细解析结果；分类编辑只作为异常修正或补录能力保留。

### 对账确认流程中的明细分类

费用明细分类发生在“银行流水匹配审批明细”的确认动作里：

1. 财务先选择一笔待匹配银行流水。
2. 系统推荐可匹配的审批单费用明细。
3. 财务选中一条审批明细后点击“匹配并分类”。
4. 弹窗同时展示银行流水摘要和审批明细摘要。
5. 财务选择入账月份、一级分类、二级分类，并确认银行流水是否已发生。
6. 系统创建并确认 `expense_bank_matches`，同时把一级/二级分类写入对应 `expense_items`。
7. 报表按 `expense_items.category_l1/category_l2` 聚合支出分类。

这个流程更符合做账动作：只有当银行流水和审批明细建立付款关系时，分类才是一个明确、可审计的财务处理结果。审批单管理页只显示“待分类/已分类”，并提供回看入口。

对账金额支持拆分：一笔银行流水可以拆分匹配到多条审批明细，一条审批明细也可以分多笔银行流水付款。创建候选时会按已确认和待确认候选占用金额校验，确认匹配时会按已确认金额再次校验，避免银行流水或审批明细超额入账。
