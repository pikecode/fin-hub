# 钉钉同步评估复核与处理计划

日期：2026-09-04

## 背景

本文基于 `docs/2026-09-04-dingtalk-sync-evaluation.md` 对当前代码实现做二次复核。原评估报告整体方向正确，但其中部分问题在当前代码中已经修复或部分修复，因此后续处理需要按真实代码状态重新排序。

## 当前已实现

1. 自动同步窗口已调整为 `window_days=14`、`approval_overlap_days=2`。
2. 审批同步已有 `SELECT ... FOR UPDATE` 行级锁，用于锁定已存在的审批实例。
3. 部门同步到门店时，已经避免同名门店直接误绑定；同名冲突会创建带钉钉部门 ID 后缀的新门店。
4. 钉钉同步相关查询索引已有迁移覆盖，包括审批实例、支出明细、门店钉钉部门 ID、同步任务状态等。
5. 模板同步已额外调用钉钉流程节点接口，并写入 `approval_template_nodes`。

## 仍需处理的问题

### 1. 支出明细幂等约束不完整

`ExpenseItem.source_document_id` 是钉钉审批明细同步的幂等键，但当前只有普通索引，没有数据库唯一约束。代码层先查再写，在并发、重试或历史脏数据下仍可能产生重复支出明细。

建议：

- 增加数据库层唯一约束。
- 约束范围使用 `source + source_document_id`。
- 排除 `source_document_id IS NULL`，避免影响手工支出。
- 建约束前先对历史重复数据做保守去重。

### 2. 同步任务缺少任务级互斥

审批实例行级锁只能保护已存在的审批实例。首次同步新审批时，两条同步任务仍可能同时查不到同一审批实例，然后同时创建，最终依赖唯一约束报错兜底。

建议：

- 在启动手动审批同步、恢复同步、自动同步前检查是否已有运行中的钉钉同步任务。
- 覆盖 `dingtalk_approval_sync`、`dingtalk_store_approval_sync`、`dingtalk_auto_sync`。
- 手动触发时返回 409，自动调度时跳过本次执行。

### 3. 字段候选只取最新一条审批

字段候选提取目前只读取最新一条审批实例。如果最新审批没有填写某些条件字段或明细字段，映射页面会漏掉可配置字段。

建议：

- 改为读取最近 10 条有 `raw_payload` 的审批实例。
- 合并字段候选并去重。
- 保留已有的“优先使用有样例值字段”的去重逻辑。

### 4. 状态字段语义重叠

`parse_status` 和 `processing_status` 的职责边界不够清晰。这个问题短期不一定导致数据错误，但会增加列表筛选、报表统计和后续维护成本。

建议：

- 暂不作为本轮优先处理。
- 后续单独设计状态迁移，避免影响审批列表、支出明细、对账和报表。

## 本轮处理优先级

1. 加 `ExpenseItem(source, source_document_id)` 部分唯一索引，并在迁移里处理重复历史数据。
2. 加钉钉同步任务级互斥。
3. 字段候选改为最近 10 条审批合并。

## 验证建议

1. 后端单元测试覆盖：
   - 字段候选合并最近多条审批。
   - 手动审批同步已有运行中任务时返回 409。
   - 自动同步调度遇到运行中任务时跳过。
2. 执行 API 测试：
   - `uv run pytest tests/test_dingtalk_templates.py tests/test_dingtalk_sync_optimization.py`
3. 执行迁移检查：
   - 本地升级到最新 head。
   - 确认重复支出明细不会阻塞唯一索引创建。
