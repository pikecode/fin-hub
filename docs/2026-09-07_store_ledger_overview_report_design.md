# 门店总览报表化设计

日期：2026-09-07

## 背景

当前门店总览页同时承担了：

- 经营结果概览
- 对账进度提示
- 银行流水、经营收入、审批单明细查看

这导致页面信息密度高，但主线不清晰。需要把总览页升级为“报表统计页”，先看结论，再下钻明细。

## 目标

1. 把总览页从“工作台”改成“报表页”。
2. 统一各项统计口径，避免口径混乱。
3. 保留门店维度、账期维度和对账维度的下钻能力。
4. 让用户一眼看懂本期经营结果、审批支出、经营收入和分类分布。

## 建议页面结构

### 1. 顶部筛选

- 门店
- 账期
- 维度切换：按日、按渠道、按分类、按状态
- 导出

### 2. 核心指标区

建议保留 5 到 6 个卡片：

- 经营收入
- 实收
- 本期支出
- 本月审批金额
- 本期结余
- 待处理项

### 3. 趋势分析区

- 收入趋势
- 支出趋势
- 审批金额趋势
- 对账进度趋势

### 4. 结构分析区

- 收入渠道占比
- 支出分类占比
- 审批模板占比
- 银行流水类型占比
- 审批处理状态分布

说明：报表层只保留 `已匹配 / 未匹配`，不展示 `未解析 / 待分类 / 待匹配 / 同步冲突` 这类内部处理状态。

### 5. 下钻明细区

- 银行流水
- 经营收入
- 审批单
- 对账记录
- 异常记录

## 指标口径

### 经营收入

按录入日期统计当前账期内各渠道经营收入的累计金额。

说明：

- 来源是 `revenue_records`
- 统计维度以录入日期为准
- 不是按银行流水，不是按审批单

### 实收

按经营收入录入时填写的 `net_amount` 汇总。

说明：

- 来源是 `revenue_records.net_amount`
- 用于反映实际收回金额

### 本期支出

按对账后确认的审批支出统计当前账期金额。

说明：

- 来源是 `expense_items`
- 口径以审批单为主
- 如果审批单明细未完全分类，仍应保留审批单主记录

### 本月审批金额

按审批单创建时间统计当前月份审批通过金额。

说明：

- 来源是 `approval_instances`
- 口径以审批单主金额为准
- 与支出分类统计不同，不强制要求全部明细已分类

### 支出分类统计

按当前账期各支出的二级分类汇总。

说明：

- 来源是 `expense_items`
- 展示到二级分类
- 支持按分类钻取到审批单

## 建议的实现方案

### 方案一：在现有总览页上重构

保留当前路由 `/store-ledgers/[storeId]`，但重做版式和统计卡。

优点：

- 改动小
- 用户路径不变
- 现有下钻能力可以直接复用

缺点：

- 明细和报表还是在一个页面里，后期可能继续变重

### 方案二：总览页改成报表中心，明细页另开

把 `/store-ledgers/[storeId]` 改成纯报表页，明细继续放到：

- `/bank`
- `/revenue`
- `/finance/reconciliation`
- `/finance/revenue-reconciliation`
- `/store-ledgers/[storeId]/approvals`

优点：

- 总览更清晰
- 更适合做仪表盘

缺点：

- 需要调整用户对“总览页”的心理预期

## 推荐方案

先采用方案一。

原因：

- 能最快把口径和视觉统一起来
- 不破坏现有工作流
- 后续再拆成独立报表中心也容易

## 后端改造建议

### 1. 补充报表统计字段

建议在 `StoreLedgerWorkspaceMetrics` 里补充：

- `gross_income_amount`
- `net_income_amount`
- `approval_month_amount`
- `expense_category_breakdown`
- `revenue_channel_breakdown`

### 2. 报表聚合接口

建议新增单独的报表聚合接口，避免 workspace 接口继续膨胀。

例如：

- `/store-ledgers/{store_id}/report-summary`

返回：

- 核心指标
- 趋势数据
- 分类分布
- 下钻计数

补充字段建议：

- `approval_month_amount`：按审批创建/提交时间统计审批金额
- `approval_status_summary`：按 `processing_status` 统计审批状态分布
- `bank_transaction_count`：用于银行流水趋势图展示流水笔数

### 3. 审批与收入口径分离

审批单只负责：

- 审批主金额
- 审批明细分类
- 审批匹配状态

经营收入只负责：

- 渠道收入
- 实收
- 录入日期
- 费率

不要在总览层把两者混成同一个口径。

## 前端改造建议

### 1. 头部

- 门店名做主标题
- 账期做次级标签
- 关键状态做标签

### 2. 指标卡

- 统一高度
- 统一数字字号
- 主指标加大
- 说明文字弱化但保留

### 3. 图表区

- 先趋势，后结构
- 每个图表都能点进明细

### 4. 明细区

- 放到页面下半部分
- 默认折叠或只展示当前最常用一个 tab

## 风险点

1. 口径冲突：经营收入、实收、审批金额不能混用。
2. 数据量：单页同时加载图表和明细，接口要做聚合和分页。
3. 用户认知：要让用户明确“总览看结果，详情看明细”。

## 后续实施顺序

1. 先定义报表口径。
2. 再补后端聚合字段。
3. 再重做总览页布局。
4. 最后补图表和下钻。

## 图表组件补充方案

### 1. 引入真实图表组件

前端已经安装 `echarts` 和 `echarts-for-react`，总览页应使用统一图表组件，而不是手写 CSS 条形图。

建议新增两个总览专用图表：

- 银行流水图表：展示当前账期收入流水、支出流水、未匹配流水金额。
- 渠道月度收入图表：以月份为横轴，展示各经营收入渠道的经营收入。

### 2. 经营收入按月展示

总览页当前是单账期视图，但用户需要看“各个渠道的情况，以月份为单位”。

后端 `workspace` 可以先返回当前账期往前 6 个月的数据：

- `period`
- `channel`
- `gross_amount`
- `net_amount`
- `record_count`

前端按 `period + channel` 组装堆叠柱状图。

报表页同时建议补一张“经营收入渠道月度图”，先看月份变化，再看本期结构。

### 3. 推荐交互

- 默认展示经营收入 `gross_amount`。
- tooltip 展示月份、渠道、经营收入、实收金额、记录数。
- 渠道用 legend 控制显示隐藏。
- 当前账期依然保留渠道汇总表，图表负责看趋势，表格负责看本期结构。
