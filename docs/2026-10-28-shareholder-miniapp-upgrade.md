# 股东小程序完善方案与实施记录

## 定位与权限

小程序为授权门店经营信息的只读端。采用后台已有用户的用户名、密码登录，建议管理员创建“查看者”账号、分配门店；不再在小程序使用旧授权码。后台旧授权接口暂保留兼容，不自动迁移旧授权为用户。

小程序独立签发 12 小时的带类型凭证，仅 miniapp 接口接受，不签发管理端 Cookie。接口每次检查账号启用状态、权限及门店范围；改密使旧凭证失效。后台登录解析明确拒绝小程序及旧股东类型凭证，防止凭证混用。自定义角色须具备报表查看权限，流水与筹建模块还沿用对账查看权限。

## 页面及数据口径

- 登录 → 授权门店列表 → 门店工作台。工作台顶部切换门店，内部包含财务报表、营业收入、银行流水、筹建报表、分红管理五个模块；个人中心独立页面。
- 财务报表：只允许已封账月份，复用 Web 财务报表 metrics、补充资料及分类金额；展示营收、实收、手续费、目标、支出、毛利、净利、核心成本率、渠道、分类、分红和资金。分类可查看分月费用金额及凭证。
- 营业收入：按经营日期所属月份读取；渠道统计完整月份，明细分页每页 30 条，展示总条数。
- 银行流水：实时只读，不要求封账；发生日期起止（含结束日）与关联状态筛选，独立展示当前余额，列表每页 30 条，点击查看支出报销、报销总额、分类内容、凭证及收入关联日期。余额无校正基准时不显示为真实零余额。
- 筹建报表：不分账期，读取确认匹配的筹建原金额和费用明细；不展示候选对账或操作入口。
- 分红：只允许已封账月份，复用期初隔离和历史计算；筛除未封账历史记录。旧口径月份读取禁止新建月份，以免只读访问产生业务数据。
- 个人中心：账号资料、授权门店数量、改密、退出；改密后重新登录。

所有日期选择采用中文显示；请求失败显示具体提示。切换门店、月份、模块时清空旧数据显示加载状态，并以请求序号阻止旧响应覆盖新结果。

## 实施边界与上线

本次不改变旧 `/reports/ledger-*` 接口，以免影响历史客户端；新小程序使用 `/api/miniapp/*` 及 Web 共用计算服务，不继续消费旧版账期费用原额汇总。财务报表移动布局为简化卡片版，不直接嵌入 Web 页面。

无需数据库迁移。上线需先发布配套 API，再使用新构建上传微信开发者工具。接口默认域名为 `https://fin.moshuo.fun`，可用 `TARO_APP_API_BASE_URL` 覆盖；微信后台需配置 request/downloadFile 合法域名。项目未包含真实 AppID，本次不代为发布微信审核。

尚需微信开发者工具及真机验收，重点检查图片与 PDF 凭证预览、中文日期、低速网络和窄屏布局。本次未部署服务器、未修改生产数据。

以餐饮门店股东查看财务的场景为基础，采用墨绿 `#214F42`、暖灰 `#F5F5F1`、白色卡片；主文案与金额使用深墨色，次要说明使用灰绿，仅错误使用低饱和红色。取消此前绿色/蓝灰多套主题叠加。

- 统一全局字体、边距、圆角、金额数字样式、筛选、输入和按钮。页面级 CSS 只保留布局差异，删除旧版本排行/图表/卡片遗留样式。
- 财务主指标“营业收入”使用深绿整行卡片，其余指标使用两列紧凑网格；分类、业务和历史明细保持白底分隔线列表，降低装饰性阴影。
- 门店使用编号、名称、箭头和业务范围；删除门店页、经营页重复的个人中心按钮，统一从底部“我的”进入。
- 账户卡片增加文字头像与信息层级。退出登录使用低权重描边，保存操作使用主色。
- 原生 TabBar 提供门店、经营、我的三组 81×81 透明 PNG 图标，选中墨绿、未选中灰绿；统一线宽及占比。图标通过程序绘制，为静态工程资源。
