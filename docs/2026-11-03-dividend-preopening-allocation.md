# 分红管理与筹建超支分配

## 业务口径

分红管理按门店、月份分别记录股东分红、补充筹建超支和运营增资。补充筹建超支使用经营利润，减少未分配利润，不计入股东分红，不再作为费用重复扣减报表净利润。

- 筹建结余 / 超支＝筹建投入资金－筹建费用总支出。非负显示结余；负数显示超支的绝对值。
- 筹建报表已封账：支出使用筹建报表的原始审批费用合计，整单与明细去重、多笔付款不重复累计，优先于历史人工覆盖值。
- 筹建报表未封账：使用人工录入的总支出；未填则页面及导出显示待录入 / 待计算，不能按缺失数据分配超支。
- 经营利润已补充＝期初历史实际已补充＋隔离月份起、截至查看月份的实际补充记录。原有“累计利润与超支取较小值”的估算不再使用。
- 超支未补充＝筹建超支－经营利润已补充。保存时累计补充不能大于筹建超支。
- 本月可分配利润＝上月期末未分配利润＋本月净利润。
- 期末未分配利润＝本月可分配利润－本月股东分红－本月补充筹建超支。运营增资不参与此公式。
- 历史累计分红仅累计股东分红；历史累计利润仍为净利润累计，不因利润用途变化而减少。

## 页面与操作

指标按经营利润与分配、筹建资金、运营增资、历史累计分组，用分割线区分，分红比例和月份锁定另列为分配设置。

“录入本月分配”提供“分配分红 / 分配筹建超支”单选。分红沿用股东明细；补充超支按门店录入一个总金额及备注，无需股东。二者可在同月分别保存，不相互覆盖。“本月分配利润”更名为“本月分红”；历史明细新增补充金额、记录展示与编辑入口。

补充金额按月覆盖保存，重复保存不会重复累加。填 0 清除该月补充；审计保留修改前金额、修改后金额、备注及操作人和时间。股东分红 / 增资保存时前端核对总额与明细合计。

全公司合并只包含未被数据隔离的门店月份，各门店超支和结余分别汇总，不互相抵扣，超支未补充逐店求和。

## 期初与约束

期初增加“历史经营利润已补充筹建超支”，默认 0，必须按真实已确认金额录入。期初剩余未分配利润应为已经扣除历史补充后的余额，系统不再重复扣减。

筹建超支初值通过期初的筹建投入与筹建总支出维护，不增加与这两个基础金额相冲突的独立覆盖值。报表封账后总支出只读，使用已封账报表金额。

未设置期初的旧门店可继续查看原有分红数据，但应先确认期初再分配筹建超支。隔离前记录只读保留，不计入新增累计。新增操作仍仅管理员可写，沿用门店授权。

后端对同店写操作使用事务级锁；校验累计补充上限，并逐月重算利润分配，防止修改早期月份导致后续已分配金额透支。没有分配的亏损月可正常保留。有受影响的锁定分红月份或封账账期时阻止修改。期初修改沿用版本冲突和锁定 / 封账检查。

筹建封账同样持有门店分红锁；切换到真实筹建报表总额后，如果已有补充超过新的超支金额，则拒绝封账并回滚，避免数据源切换绕过限额。

## 报表、导出及迁移

财务报表页面、HTML 以及 PDF 共用的报表模板同步显示本月分红、本月补充、筹建结余 / 超支和实际补充情况。PDF 继续使用现有分页与宽度逻辑。

新增迁移 `20261103_0040`（上版 `0039`），只给 `dividend_opening_balances` 增加非空 `historical_preopening_coverage Numeric(14,2)`，默认 0。月度补充记录复用 `dividend_entries`，类型为 `preopening_coverage`，不关联股东。旧分红、增资和期初余额不改写，不将旧估算转成实际补充。

上线前备份数据库，API 和管理端配套发布并执行迁移。应用回滚需优先保留新列和补充记录；已有实际补充后，旧版余额公式无法识别此类记录，不应直接切回旧口径继续办理分配。应暂停该功能并修复前进，或专项核对迁移期间数据后再决定回退。不要直接 downgrade 删除历史已补充值。
