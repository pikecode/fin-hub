# 股东财务小程序只读需求与实施核对

日期：2026-11-09。基于现有 Taro 微信小程序及 `/api/miniapp` 接口完善，既有实现及发布历史见 [小程序升级记录](2026-10-28-shareholder-miniapp-upgrade.md)。

> 2026-11-10 更新：按用户新需求取消“仅封账可查看”限制，改为四个底部入口，详见 [本批说明](2026-11-10-miniapp-navigation.md)。本文下方发布补记保留原始历史事实。

## 目标与授权

股东、股东财务通过账号登录查看授权门店报表、流水业务及每月分红。后台“用户管理”选择“查看者”或自定义只读角色，配置多个门店、多个门店分组或两者组合。自定义角色至少具有报表查看及对账查看权限；不授予业务管理权限。

有效门店范围为直接授权门店与授权分组内门店的并集，每次请求实时解析，不把当前分组成员复制为静态授权。新增门店加入分组自动可见；门店移出分组或分组授权撤销后，若无其他直接或分组授权即不可见。停用账号、修改密码及移除角色权限按现有凭证校验生效。

复用现有用户、角色、UserStorePermission、UserStoreGroupPermission，不新建重复授权体系。小程序专用凭证不能用于管理端业务写接口。个人改密不属于财务业务写操作，继续保留。

## 页面与数据口径

| 模块 | 展示及规则 |
| --- | --- |
| 报表 | 按月份查看已封账及未封账门店报表，未封账数据标记为动态更新；报表内含财务报表和营业收入，左上角切换授权门店，复用后台计算服务。 |
| 银行流水 | 独立于账期，按发生日期、关联状态筛选并分页。展示金额、方向、发生日期、关联状态；点击行查看对应报销或营业收入业务及凭证。 |
| 流水详情 | 列表“详情”按钮与业务详情页展开入口；展示对方户名/账号、流水号、属性、直接入账类型、付款情况、已匹配金额、入账月份、备注、录入/更新时间；不提供编辑、匹配、删除。 |
| 分红管理 | 按已创建账期展示净利润、可分配利润、剩余未分配利润、本月分红/运营增资/补充筹建超支、累计利润/分红/运营增资/超支补充、建议分红及分配明细。展示选中月筹建投入/费用/结余或超支、已补充/未补充及累计投入；财务录入操作不提供。 |

金额缺失显示“—”，不当作真实零余额。筹建超支补充分配与股东分红、注资分别显示，不混用名称。授权范围内已创建的未封账月份同样可见。

## 本次实施

- 复核现有后台多门店/多分组授权、动态范围计算、账号只读凭证、月份封账限制和门店切换，保留既有实现。
- 补充银行流水列表“详情”按钮及完整业务字段展示，加载新详情时清空旧数据。
- 分红接口增加只读补充数据，复用财务报表服务；移动页面补充累计与筹建相关信息，修复补充筹建超支被标为注资的问题。
- 移动报表银行余额改用“报表银行余额”，不再误写次月10日；增加上月末利润、历史利润、更名累计投入。
- 新增动态分组授权测试：签发凭证后新增门店继承权限、移出分组即时拒绝、撤销分组授权即时拒绝、直接授权继续保留、跨店流水拒绝。

## 验证与上线边界

本地 PostgreSQL 隔离 schema 小程序测试 4 项通过，覆盖封账、跨门店访问、只读凭证隔离、密码/状态失效及新增分组回归。类型检查与微信生产构建结果见 CHANGELOG。

本次不修改生产账号授权、不发布生产 API、不上传微信审核。发布需先更新配套 API，再上传小程序构建产物，并用微信开发者工具及真机验收登录、不同账号范围、切换门店月份、长备注/账号展示、凭证预览和分红页面。构建成功不等同于微信真机验收通过。

依赖工作区同期报表补充字段；发布前需要审核其他未完成计提单及余额校正改动的范围，不能把本需求完成等同于所有工作区需求完成。
