# 银行流水余额校正设计规划

## 1. 需求理解

在银行流水页面增加“银行余额校正”能力，用于把系统计算出的余额与银行实际余额对齐。用户每次录入一个实际银行余额、录入日期和备注，系统新增一条余额校正记录，作为该日期之后余额计算的基准。校正不会修改或删除历史银行流水。

本次规划对应银行流水页面，余额按当前门店统计。余额计算使用该门店的全部银行流水，不能只统计当前列表筛选结果。

## 2. 页面交互

### 2.1 银行余额区域

在银行流水页面顶部增加银行余额区域，显示：

- 当前实时银行余额
- “录入银行余额”按钮
- “查看余额校正记录”按钮

实时余额的计算结果要明确标注为“实时余额”，避免与当前账期收入、支出累计金额混淆。

### 2.2 录入银行余额

点击“录入银行余额”后打开弹窗，表单包括：

- 录入日期：必填，表示这个余额对应的日期
- 银行余额：必填，表示该日期的实际银行余额
- 备注：必填，用于记录调整原因

用户填写后点击保存，先弹出二次确认，展示录入日期、银行余额和备注；用户确认后，再要求输入当前用户密码，密码验证通过后才正式保存。

密码错误或取消确认时不保存记录。校正记录创建后不可编辑、不可删除。

### 2.3 查看余额校正记录

点击“查看余额校正记录”后打开列表弹窗，按校正日期倒序展示：

- 校正日期
- 校正后余额
- 备注说明
- 录入人
- 录入时间

列表不提供编辑和删除操作。若发现录入错误，通过新增一条正确的校正记录纠正，并保留原记录形成完整审计链。

## 3. 余额计算规则

### 3.1 基准规则

余额校正记录的“银行余额”是录入日期当天的实际余额。取当前门店最新的一条余额校正记录作为计算基准。

### 3.2 后续流水调整

从该校正记录的录入日期之后开始，按银行流水发生日期累计。录入日期当天的流水不参与本次校正后的计算：

- 收入：余额增加流水金额
- 支出：余额减少流水金额

实时余额 = 最新校正余额 + 校正日期之后的收入合计 - 校正日期之后的支出合计。

计算使用流水发生日期，不使用流水录入日期。也就是说，用户可以后补录历史流水，但只要流水发生日期在校正日期之后，就会参与余额计算。

示例：

```text
8 月 31 日录入银行余额：10,000，备注“月底对账调整”
9 月 1 日收入：+2,000
9 月 2 日支出：-500
当前实时余额：11,500
```

### 3.3 没有校正记录时

如果该门店还没有余额校正记录，页面显示“暂无银行余额”，并提示先录入银行余额。此时不直接把流水收支合计当作银行余额。

### 3.4 特殊流水

往来款、股东分红、股东注资、其他收支都是实际银行流水，因此都参与银行余额计算。它们是否进入审批单对账、收入对账的规则保持现有逻辑，不影响余额计算。

## 4. 数据设计

新增独立的银行余额校正记录表，建议字段：

- `id`
- `store_id`
- `correction_date`：余额录入日期
- `balance_amount`：该日期的实际银行余额
- `remark`：必填备注
- `created_by`：录入用户
- `created_at`
- `updated_at`

建议增加 `store_id + correction_date` 索引。校正记录不与 `bank_transactions` 混在一起，避免影响现有流水匹配、删除和报表逻辑。同一天允许多次调整，使用最后一次录入的记录作为当天及之后的最新基准，并保留全部历史记录。

## 5. 接口设计

建议新增接口：

- `GET /api/bank-balance/corrections?store_id=...`：查询全部余额调整记录
- `POST /api/bank-balance/corrections`：创建余额调整记录
- `GET /api/bank-balance?store_id=...`：返回当前余额、最新调整日期以及调整日期之后的收入和支出合计

创建接口接收当前用户密码，仅在服务端验证密码。不能在前端判断密码后直接保存，也不能把密码写入日志或审计元数据。

建议余额接口返回：

```json
{
  "balance_amount": "11500.00",
  "base_balance_amount": "10000.00",
  "base_correction_date": "2026-08-31",
  "income_after_base": "2000.00",
  "expense_after_base": "500.00",
  "has_correction": true
}
```

## 6. 权限和封账

- 查看余额和校正记录需要银行流水查看权限。
- 新增余额校正需要银行流水管理权限。
- 对应账套封账后不允许新增余额校正。
- 历史校正记录始终只读，不提供删除接口。
- 服务端再次校验门店权限和账套状态，不能只依赖前端按钮禁用。

## 7. 与现有页面的关系

- 顶部“本月收入累计”和“本月支出累计”继续表示当前筛选月份的流水累计，不改成银行余额。
- 银行余额单独展示，统计范围为该门店全部流水及最新余额校正日期之后的流水。
- 银行流水新增、编辑、批量录入成功后，实时余额自动重新计算。
- 银行流水删除、批量删除成功后，实时余额自动重新计算。
- 流水属性筛选、匹配状态筛选和日期筛选不改变实时余额的计算口径。

## 8. 实现和验证顺序

1. 新增数据库表和迁移。
2. 增加校正记录查询、创建和余额计算接口。
3. 增加密码校验、权限校验和封账校验。
4. 银行流水页面增加实时余额区域和两个操作弹窗。
5. 新增、编辑、删除、批量录入后刷新余额。
6. 增加接口测试和余额计算测试。
7. 使用收入、支出、特殊流水、跨账期流水和多次余额调整记录验证计算结果。

## 9. 已确认口径

- 每次调整都新增记录，历史记录不能删除。
- 余额调整记录包含录入日期、银行余额和备注。
- 只计算调整日期之后的银行流水，调整日期当天流水不参与本次基准后的计算。
- 收入增加余额，支出减少余额。
- 余额调整不改变任何银行流水，也不参与审批单对账和收入对账匹配。
