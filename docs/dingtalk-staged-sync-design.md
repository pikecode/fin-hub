# 钉钉分阶段同步设计

## 背景

钉钉审批单同步依赖两个前置资料：

- 部门：用于识别审批单所属门店。
- 审批模板：用于决定哪些审批单进入系统，以及如何解析金额、日期、明细和凭证字段。

因此审批单不应该和部门、模板混在一个无条件同步动作里。正确流程是先同步基础资料，再由财务确认模板启用和解析规则，最后同步审批单。

## 推荐流程

1. 配置钉钉应用凭证。
2. 同步钉钉部门快照。
3. 将候选门店部门落库或映射到门店档案。
4. 同步审批模板快照。
5. 启用需要参与财务处理的模板。
6. 为启用模板配置解析规则。
7. 同步审批单。

## 审批同步前置条件

后端统一通过 `GET /api/dingtalk/sync-readiness` 返回审批同步是否就绪。

审批单同步必须满足：

- 钉钉应用凭证完整。
- 已有钉钉部门快照。
- 至少有候选门店部门完成门店映射。
- 已有审批模板快照。
- 至少启用一个审批模板。
- 所有启用模板都已配置业务解析规则。

不满足时：

- 手动审批同步按钮禁用。
- 后端同步接口继续保留兼容能力，仍以模板启用状态作为硬约束。
- 自动同步如果开启了审批同步，会只处理启用模板。

这样可以保证页面流程足够清晰，同时不破坏已有的样例拉取、历史补拉和默认字段兜底解析能力。

## 自动同步策略

自动同步仍然保留三个独立开关：

- 同步部门和门店。
- 同步审批模板。
- 同步审批单。

建议首次接入时只开启部门和模板同步。财务完成模板启用和字段配置后，再开启审批单自动同步。

审批单增量同步使用钉钉审批更新时间作为主要判断依据：

- 新数据：按审批实例 ID 新增。
- 已存在数据：对比 `dingtalk_modified_at`，必要时重新拉取详情并重新解析。
- 自动同步水位：使用 `approval_watermark_at`，并保留短时间 overlap，避免边界数据漏同步。

## 同步模式

当前实现中，部门同步和审批同步的模式边界不同：

- 部门同步：只要钉钉凭证可用，就调用钉钉部门接口同步真实部门树。
- 审批模板同步：受 `DINGTALK_SYNC_MODE` 控制。
- 审批列表同步：受 `DINGTALK_SYNC_MODE` 控制。

`DINGTALK_SYNC_MODE=mock` 时，审批模板和审批列表使用本地演示数据，便于开发联调。要拉取真实审批模板和真实审批单，需要用 `DINGTALK_SYNC_MODE=real` 启动 API 服务。

模板同步调用钉钉 `process/listbyuserid`，按管理员 User ID 查询该管理员可见的审批模板。接口按 offset/size 翻页，直到最后一页不足 page size，避免模板超过 100 个时只同步第一页。

## 对账关系

同步后的审批单分为两层：

- 审批单主表：保存钉钉实例、申请人、部门、状态、提交时间、完成时间、更新时间和原始 JSON。
- 审批单明细表：保存系统解析后的财务明细，用于银行流水匹配、入账分类和后续报表。

银行流水对账只处理系统格式化后的审批数据，不直接读取钉钉原始 JSON。

一个银行流水可以匹配一个审批单，也可以匹配审批单下的多条明细。匹配确认后需要记录：

- 银行流水 ID。
- 审批单 ID。
- 审批明细 ID，可为空。
- 入账月份。
- 入账分类。
- 确认金额。
- 匹配状态。

明细分类发生在对账确认流程中，用于后续统计分析。

## 审批节点名称映射

钉钉审批实例详情当前同步到的 `tasks` 里有 `activity_id`、审批人、状态和时间，但不一定包含可读节点名称。因此系统增加模板级节点映射：

- 表：`approval_template_nodes`
- 唯一键：`template_id + activity_id`
- 字段：`activity_id`、`node_name`、`node_type`、`sort_order`、`is_active`

使用逻辑：

- 审批模板的“解析规则”抽屉中维护节点名称。
- 审批实例接口返回 `node_name_map`，格式为 `{ activity_id: node_name }`。
- 审批详情流程展示优先使用 `node_name_map[activity_id]`。
- 未配置节点名称时，页面显示 `审批节点 {activity_id}`，避免误展示。

这个设计先支持手工配置，后续如果钉钉模板详情接口能够稳定返回流程节点定义，可以直接写入同一张表，实现自动补全或半自动校验。

## 手动审批同步取消

后台管理的手动审批同步使用后台任务模式：

- 发起同步时先创建 `sync_jobs` 记录，状态为 `running`，接口立即返回。
- 页面同步任务表展示运行中任务，并提供“取消”操作。
- 取消接口：`POST /api/dingtalk/sync-jobs/{job_id}/cancel`。
- 取消后任务状态更新为 `canceled`，`error_message` 记录为“同步已取消”。
- 同步循环在模板、分页、审批实例和补重试阶段都会检查任务状态。

取消是协作式取消，不会强行中断已经发出的钉钉 API 请求，也不会回滚已经成功落库的审批实例和明细；它会在当前处理步骤结束后停止后续分页和后续实例处理。
