# 银行流水门店与账期归属设计

## 背景

银行流水是门店资金发生凭证。当前业务要求是：每个门店维护自己的银行流水，流水不能跨门店使用；但流水不需要按账期复制，同一门店只维护一份原始流水数据。

## 核心口径

- 银行流水必须归属门店：`bank_transactions.store_id` 必填。
- 银行流水只按门店隔离，不绑定工作区账期。`bank_transactions.ledger_period` 暂保留为历史兼容及既有封账校验元数据，不作为管理页默认查询条件。
- 银行流水的 `ledger_period` 可以与 `occurred_at` 的月份不同；`occurred_at` 才是真实银行发生日期。
- 匹配记录的 `accounting_period` 表示入账账期，是总览本期支出、收入对账、报表对账口径的依据。
- 银行流水不按账期复制；同一门店的一条流水可以在不同账期页面被查看或用于匹配，但匹配时必须留下明确的 `accounting_period`。

## 匹配规则

### 2026-11-05 按门店查询与报表来源追溯（最终口径）

银行流水管理页默认展示当前门店全部发生日期的流水，切换工作区账期不改变列表范围。移除“列表账期”“查询全部账期”“返回当前账期”及跨期直接入账提示，保留发生日期、金额、户名等筛选和报表来源精确 ID 定位。列表不展示历史所属账期及以其计算的跨期标记，保留真实入账月份。

单条新增、批量录入和文件导入只选择门店。新流水内部兼容月份按各自发生日期确定；编辑已有流水保留历史元数据。导入不传工作区月份，多月文件按行解析发生月份。列表重置清空日期等筛选。上方统计日期默认当前自然月，可独立调整，不受工作区月份影响；统计卡片与列表日期筛选分别维护。

API 新增只读跨期汇总 `/api/bank-transactions/cross-period-direct-postings?store_id=&period=`，接口保留 `posting_period`、`cross_period_only` 和 `ledger_period` 供既有调用方显式使用，管理页不再传这些账期过滤参数；来源跳转使用 `transaction_id`，沿用门店访问权限且排除归档流水。列表返回非持久化的 `accounting_periods`。

财务报表的银行相关费用详情、特殊流水表增加来源跳转。原流水定位按门店和流水 ID 查询，不受所属账期筛选影响，避免从 10 月报表跳转后仍看不到归属 9 月的流水；列表明确显示定位范围。HTML / PDF 共用模板保留所属账期、入账月份和来源编号，HTML 链接使用导出时站点地址。PDF 沿用现有分页，后续页为图片，不保证每页链接可点击，可用来源编号追溯。

本次仅改进展示和查询，不批量更改历史日期、归属元数据、入账金额、银行余额或利润规则，保留既有封账、匹配和付款核对保护，无数据库迁移，尚未部署生产。

- 支出审批单和银行流水必须属于同一门店。
- 收入记录和银行流水必须属于同一门店。
- 审批单账期、收入记录账期、银行流水归属账期、银行真实发生月份可以不同。
- 跨期时，用户在匹配确认中选择 `accounting_period`，系统按该账期统计对账结果。
- 匹配金额由用户确认，系统不再因为剩余金额不一致阻止保存。

## 页面与统计口径

- 银行流水管理页：按门店查询，不随工作区账期过滤；需要限定日期时由用户选择发生日期。
- 审批单对账页：选中某条银行流水后，候选审批单只来自该流水所属门店。
- 门店总览本期支出：按已确认支出匹配记录的 `accounting_period` 汇总。
- 银行流水趋势和未匹配流水：按银行流水归属账期 `ledger_period` 汇总。

## 数据治理

历史数据里如果存在 `store_id` 或 `ledger_period` 为空的银行流水，不能自动归属到某个门店。上线强约束前必须先审计这些数据，由用户确认删除或补门店/归属账期。

## 其他收入直接入账（2026-11-05）

在银行流水“直接入账属性”选择“其他收入”，只允许已实收的收入流水。按发生日汇总到同门店、同日的“其他收入”收入记录，入账月份取发生月份，不取列表所属账期；手续费为零，金额计入报表收入及利润。与“银行结息”分渠道统计，与特殊流水“其他收支”区分。页面、HTML / PDF 共用报表金额及标签。

该流水禁止再次匹配审批单或营业收入；自动生成的收入记录也不参与银行匹配，不能直接编辑或删除，必须从原银行流水调整。修改金额、发生日、门店或直接入账类型，以及清除属性、删除流水，都会重算受影响日期的收入，避免残留或重复；已封账月份沿用禁止变更的保护。

若已有手工维护的“其他收入”渠道，保留原渠道设置；同门店同日已有手工收入记录时拒绝直接生成并提示核对，不覆盖或叠加。存在自动收入记录期间禁止更名、删除该渠道。自动收入不要求再次匹配，不阻塞相应营业收入核对检查。新增类型使用现有字段，不需要数据库迁移。

## 审批单对账流水队列不关联账期（2026-11-05）

审批单对账“银行流水对账”左侧按当前门店查询待匹配支出流水，不传银行流水 ledger_period；移除全部 / 当前账期开关与流水卡片历史账期标签。候选审批单查询继续按门店、模板、审批号及所选流水筛选，不增加账期过滤。

创建支出匹配不再因银行流水历史所属账期封账而拒绝，银行流水只是付款匹配凭证。确认匹配的财务入账月份、多月分摊及其封账保护仍由原会计规则处理；已有确认匹配的审批沿用其原入账方案，不能将此规则理解为禁止所有后续付款关联。门店权限、特殊 / 直接入账流水排除、付款核对锁和重复匹配校验保留。历史元数据不迁移，尚未部署。
