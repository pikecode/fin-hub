# 营业收入手续费月度支出设计

## 背景
营业收入录入时，手续费在收入列表里仍然按每条收入记录展示；同时系统还要单独保存一份支出数据，作为可汇总、可报表、可对账的费用来源。

## 目标
- 营业收入录入后，自动生成或更新手续费支出记录。
- 一级分类固定为 `手续费`。
- 二级分类固定为 `{渠道名称} + 手续费`。
- 同一门店、同一账期、同一渠道可汇总成一条支出记录，也可保留明细来源，按系统实现决定。
- 若分类不存在则自动创建，存在则复用。
- 渠道删除时，可联动清理对应手续费分类，但不影响历史已入账支出。

## 口径
- 生成时机：营业收入新增、编辑、批量录入、导入后。
- 展示粒度：收入明细逐条展示手续费。
- 支出保存粒度：可按门店 + 账期 + 渠道汇总保存，也可保存明细来源后再汇总。
- 金额口径：营业收入每条记录上的手续费金额，最终汇总进入支出数据。
- 支出记录来源：`revenue_fee`。

## 数据建议
建议手续费支出记录增加来源标识：
- `source = revenue_fee`
- `source_revenue_channel = 渠道名`
- `source_revenue_period = 账期`
- `source_revenue_store_id = 门店ID`

建议可追溯关联：
- `revenue_record_id` 或 `revenue_channel_id`
- `source_reference_id`

## 生成规则
1. 收入录入后，按当前门店、账期、渠道汇总手续费总额。
2. 计算该门店该账期该渠道的手续费支出总额。
3. 若不存在对应手续费支出记录，则创建。
4. 若已存在，则更新金额与备注。
5. 备注建议包含渠道名和账期，便于审计。

## 分类规则
1. 创建渠道时，检查是否存在对应二级分类。
2. 不存在则创建：
   - 一级分类：`手续费`
   - 二级分类：`{渠道名称} + 手续费`
3. 删除渠道时：
   - 若该分类未被历史记录引用，可删除
   - 若已被引用，仅禁用或保留，不做物理删除

## 与审批支出区分
审批单对账生成的支出与营业收入手续费支出必须分开：
- 审批支出：来源 `approval_match`
- 手续费支出：来源 `revenue_fee`

报表中应分别统计，不混合。

## 待确认点
- 手续费支出记录不允许人工编辑。
- 营业收入编辑或删除后，需要同步回写手续费支出。
- 渠道删除时，仅禁用对应分类，不做物理删除。
