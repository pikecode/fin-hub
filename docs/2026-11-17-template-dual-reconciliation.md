# 审批模板双入口与整单互斥

开发分支：work/20261116-template-dual-scope-01。起于2026-11-16，跨日完成于11月17日；已于11月17日04:01部署API/PC及0050迁移，未推送远程。发布记录见[CHANGELOG](CHANGELOG.md)。

## 使用方式

模板列表增加“允许筹建/日常双入口”，默认关闭。原“是否是筹建费用”仍保留为默认归属及原有批量转换行为，不需要关闭它来开放日常入口。要让一个筹建模板也能做日常对账，保持原设置，再打开新开关。

新开关开启不会修改任何已有审批、分类或匹配。未占用且未封账的审批可在两个入口被选择，第一笔有效匹配创建时确定整张审批归属。日常候选（尚未确认）也占用审批，不能同时到筹建入口匹配；筹建确认则立即占用筹建归属。两端都使用共同的数据库事务互斥锁和审批行锁，过期页面提交也要重新检查。

一张审批单的全部明细一起归属同一处；另一处不能再匹配，不支持一张审批拆为筹建和日常两部分。可继续在同一入口用多笔流水分次匹配。已有匹配保持归属，关闭新开关也不会迁移历史。被已确认/待确认匹配、入账计划、实付入账、有效计提关联占用的单据，以及涉及已封账数据的单据，不能通过新入口改归属。解除匹配也不自动清除原入账计划等独立业务占用。

归属切换只发生在匹配写入事务，不在浏览、报表或读取候选时发生。修改整单和各明细expense_scope，清除另一套费用分类，写入归属认领审计；后续匹配仍有操作人审计。日常匹配前先核验钉钉最新来源，核验失败不先改变归属。日常候选的未归属筹建单可读取正确审批总额，但不会因此提前计入日常报表。

## 453元案例核验

审批202610042337000002450，总额64286.67元。审计时间以数据库UTC记录加8小时：

- 11月16日11:08:41，4920元银行流水被重新确认为4467元匹配，当时另有453元匹配。
- 11:08:56解除453元；随后多次恢复、解除453元，4467元匹配并未自动变成4920元。
- 统计只累计confirmed匹配金额，rejected不参与。另一笔解除不会重新分配已确认匹配金额。不能以银行流水原金额代替实际匹配金额相加。

复现测试按59366.67+453+4467=64286.67建立匹配，连续三轮解除/重新确认453，解除后均为63833.67、剩余453，另一笔保持4467。重复解除同一条返回409，不再次扣减。再将对应匹配编辑为4920，合计恢复64286.67、剩余0。

因此目前证据不支持“解除一次又多扣453”的统计缺陷；原截图差额来源是部分匹配。界面增加部分匹配提示，说明默认匹配额小于流水剩额，且解除其他流水不会自动补足。生产数据只读核查，未代为修改金额；实际调整前应核对4920元是否全部属于该审批。
