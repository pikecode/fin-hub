# 本地钉钉真实同步模式修改总结

## 1. 修改背景

本地钉钉同步页面此前显示同步模式为 `mock`，原因是项目默认配置仍使用 mock 模式。模板同步和审批列表同步在该模式下会使用本地演示数据，因此无法满足本地真实钉钉数据测试的要求。

本次修改将本地 API 的默认同步模式统一调整为 `real`，后续按标准启动脚本启动时会直接访问真实钉钉接口。

## 2. 代码修改

### 2.1 本地 API 启动脚本

文件：`scripts/dev-api-postgres.sh`

修改内容：

- 增加本地同步模式变量。
- 未主动传入 `DINGTALK_SYNC_MODE` 时，默认使用 `real`。
- 启动 `uvicorn` 时显式传入同步模式，避免启动过程丢失配置。

标准启动命令：

```bash
scripts/dev-api-postgres.sh
```

该命令会启动 PostgreSQL、Redis，执行数据库迁移和开发数据初始化，然后以真实钉钉模式启动 API。

### 2.2 API 配置默认值

文件：`apps/api/app/core/config.py`

修改内容：

```python
dingtalk_sync_mode: str = Field(default="real", validation_alias="DINGTALK_SYNC_MODE")
```

即使直接启动 API、没有额外环境变量时，配置默认值也是 `real`。

### 2.3 环境变量示例

文件：`.env.example`

修改内容：

```env
DINGTALK_SYNC_MODE=real
```

示例配置已经与本地真实测试要求一致。钉钉应用凭据不写入示例文件，也不会提交到代码仓库。

### 2.4 测试环境隔离

文件：`apps/api/tests/conftest.py`

测试夹具现在会在测试进程内显式设置 `mock`，用于保证依赖演示数据的旧测试稳定运行。真实运行环境和本地启动脚本不使用该测试配置；需要测试真实同步逻辑的测试仍然显式设置为 `real`。

这样可以区分：

- 本地开发和实际接口调用：默认真实模式。
- 单元测试：按测试场景显式选择 mock 或 real。

## 4. 当前同步行为说明

本次修改没有改变以下业务逻辑：

- 部门和门店同步逻辑。
- 审批模板同步逻辑。
- 审批单增量同步逻辑。
- 审批单去重和更新逻辑。
- 审批单明细解析逻辑。
- 门店归属和对账逻辑。

本次只改变同步数据来源模式：标准本地启动后，模板和审批数据使用真实钉钉接口；部门同步仍使用真实钉钉部门接口。

## 5. 使用注意事项

1. 修改配置后需要重启 API，已经运行的进程不会自动读取新的默认配置。
2. 本地测试前确认 API 使用的是 `scripts/dev-api-postgres.sh` 启动的进程，而不是旧的 `uvicorn` 进程。
3. 打开 `http://localhost:3000/dingtalk` 后刷新页面，页面同步模式应显示为真实模式。
4. 真实同步依赖本地数据库中已保存且有效的钉钉应用凭据。
5. 如果钉钉应用权限、管理用户、接口权限或凭据失效，真实同步会返回钉钉接口错误，需要根据错误信息处理授权或配置问题。

## 6. 结论

本地标准启动流程已经切换为真实钉钉同步模式。后续不需要再手动执行 `DINGTALK_SYNC_MODE=real scripts/dev-api-postgres.sh`，直接执行 `scripts/dev-api-postgres.sh` 即可进行真实数据测试。
